# №1 Гранд Гурмэ — прототип главной

Интерактивный прототип для показа заказчику и передачи дизайнеру.
Направление **«Перламутр и жесть»**: мир жестяной банки — золотой ободок,
лаковая икра, перламутр, лёд. Мотив — окружность.

Это не продакшн. Приоритет — ощущение от страницы и качество скролл-анимации.

### Смысловая рамка страницы

Первая версия строилась вокруг тезиса «мы эксклюзивно возим икру одного
завода». Рамка неверная и заменена целиком: **«№1 Гранд Гурмэ» — международный
бренд премиальной гастрономии, работает с 1982 года, производит и поставляет
деликатесы под собственными марками** — икра «№1 Caviar» и рыба «Siberian
Luxury Bar». Продукцию выбирают в 300 ресторанах мира; магазины и
представительства — Дубай, США, Европа, в Москве флагманский бутик в ЖК
«Золотой» на Софийской набережной; в ассортименте больше 50 европейских
гастрономических брендов, не представленных на российском рынке.

Что из этого следует для текстов:

* название завода-поставщика в заголовки не выносится — рынку оно ничего
  не говорит. В hero стоят бренд и его уровень;
* «единственный», «лучших ресторанов» и прочая превосходная степень
  **не пишется**: по закону о рекламе такие утверждения нужно подтверждать.
  «В 300 ресторанах мира» — проверяемый факт, он подтверждается списком
  и потому допустим;
* **имена клиентов на страницу не выводятся.** Заказчик называет Cipriani
  и отмеченный звёздами Мишлен Angler — они лежат комментарием в
  `src/data/brand.js` и ждут письменного согласия правообладателей.

## Запуск

```bash
npm install
npm run dev      # http://localhost:5173
npm run build    # сборка в /dist
npm run preview  # раздача /dist, http://localhost:4173
npm run pages    # пересобрать каркасы внутренних страниц (dev и build делают сами)
npm run media    # пересобрать перечень кадров панели в public/media/README.md
```

Ничего, кроме Node 18+, не нужно: бэкенда нет, ключей нет, медиафайлы
не обязательны (см. «Медиа-заглушки»).

## Публикация

Прототип живёт на Vercel: **https://grandgurme-prototype.vercel.app**
(проект `namewertys-projects/grandgurme-prototype`). Исходники —
**https://github.com/Namewerty/grandgurme-prototype**; Vercel с репозиторием
не связан, деплой идёт из CLI:

```bash
vercel deploy --prod
```

Папка привязана к проекту через `.vercel/project.json`, настройки сборки — в
`vercel.json`: команда `npm run build`, вывод `dist`, адреса без хвостового
слеша. Что стоит знать:

* **`scripts/after-build.mjs`** (шаг `postbuild`) копирует `dist/404/index.html`
  в `dist/404.html`. Локально страницу 404 подставляет middleware из
  `vite.config.js`, в собранной версии его нет, а хостинг ищет `404.html`
  в корне вывода. Без этого шага на несуществующем адресе показывалась бы
  страница-заглушка Vercel вместо нашей;
* **`.vercelignore`** держит выгрузку лёгкой: не уезжают `screenshots/` (14 МБ)
  и присланные заказчиком макеты в корне. На сборку они не влияют — сборщик
  берёт только файлы `index.html` (см. `findPages` в `vite.config.js`).

Страниц теперь 116 (из них 74 — карточки товаров), и каркасы для них
генерируются — см. раздел
«Навигация». Открываются они по-человечески: `/catalog`, `/catalog/ryba`,
`/journal/species`, без хвостового слеша и без `.html`.

## Стек

Vite + vanilla JS, обычный CSS с кастомными свойствами.
Lenis (инерция) + GSAP/ScrollTrigger (анимации). Шрифты — Prata и Golos Text
с Google Fonts. Иконки нарисованы вручную в `src/js/icons.js`, библиотек нет.

### Правило про плейсхолдеры

**В разметке и на экране плейсхолдеров нет никогда.** Прототип показывают
заказчику, и `{{N}}` в заголовке блока доверия или `{{цена}}` в карточке
товара выглядят как недоделка, а не как вопрос к клиенту.

Вместо этого в файлах данных стоит правдоподобное значение, а рядом —
комментарий с пометкой, что значение предварительное, и с указанием, откуда
брать настоящее. Ищутся такие места по слову `предварительно`:

```bash
grep -rnE "предварительн|ПРЕДВАРИТЕЛЬН|подтвержд|ПОДТВЕРЖД|ПОДТВЕРДИТЬ|уточнить|УТОЧНИТЬ" src/data
```

Из городов `#offline` по той же причине был убран Лондон; Санкт-Петербург

**Про партнёров отдельно.** В ленте стоят не имена, а типы заведений
(«Ресторан высокой кухни · Москва»). Назвать ресторан или отель своим клиентом
можно только после письменного согласия; придуманные имена тоже не годятся —
любое короткое название с большой вероятностью совпадёт с реальным заведением,
и заказчик увидит в макете чужой бренд.

## Темы: `data-theme`

Всё завязано на атрибут `data-theme` у `<html>`:

* `light` — основное направление «Перламутр и жесть» (по умолчанию);
* `dark` — альтернатива для сравнения заказчиком.

**Как переключить.** Три способа:

1. Незаметная кнопка в подвале, справа внизу: «Тема: Светлая / Тёмная».
   Выбор запоминается в `localStorage` под ключом `gg-theme`.
2. Вручную в инспекторе: `document.documentElement.setAttribute('data-theme','dark')`.
3. Жёстко в `index.html`: атрибут `data-theme` на `<html>` (перебивается
   сохранённым выбором из `localStorage` — очистите ключ `gg-theme`).

Первичная установка идёт инлайн-скриптом в `<head>`, чтобы страница не мигала.

Тёмные секции (`#hero`, `#proof`, подвал) помечены классом
`.section--dark`. Он переопределяет семантические токены внутри себя, поэтому
такие секции остаются тёмными в **обеих** темах.

### Токены

Три слоя в `tokens.css`:

1. **Палитра** — `--void`, `--void-2`, `--ink`, `--ink-mute`, `--pearl`,
   `--pearl-2`, `--gold`, `--caspian`.
2. **Константы** — `--on-dark`, `--on-dark-mute`: не зависят от темы.
3. **Семантика** — `--bg`, `--surface`, `--fg`, `--fg-mute`, `--hairline`.
   **В компонентах пользуемся только третьим слоем.**

Отдельно — текстовые версии акцентов: `--gold-fg` и `--caspian-fg`. Причина
в контрасте: `--gold` (#A98748) на перламутре даёт 2.9:1, `--caspian` — 4.3:1;
для линии этого достаточно, для текста нет. Поэтому:

* **`--gold` и `--caspian`** — линии, ободки, рамки, подчёркивания;
* **`--gold-fg` (#7C6030) и `--caspian-fg` (#0B6E6D)** — текст этими цветами
  на светлом фоне, 5.0:1 и 5.2:1.

На тёмном фоне оба `--*-fg` возвращаются к светлым значениям — переключение
описано один раз в `.section--dark`, `[data-theme='dark']` и `.header:not(.is-solid)`,
в правилах компонентов развилок нет.

Золото — только линии, ободки и акцентный текст. Заливок и градиентов нет.
Теней нет.

**Бирюзовый — только интерактив:** подчёркивания ссылок, активные состояния,
ховер, фокус, счётчик корзины. Описательные и вторичные подписи (вкусовые
дескрипторы сортов, рубрики статей) идут `--fg-mute`. Рядом с золотом второй
акцентный цвет в статичном тексте выглядел случайным.

### Скругления

Шкала из трёх ступеней, `tokens.css`. Контраст между ступенями — приём:
капсульное управление против спокойной геометрии контента. Скруглять всё
подряд нельзя, иначе приём исчезает.

| Токен | Значение | Где |
|---|---|---|
| `--radius-pill` | 999px | кнопки, переключатель «Себе / В подарок», чипы и теги, платёжные плашки, счётчик корзины, кнопки виджета |
| `--radius-card` | 14px | коллаж `#brand`, обложки статей `#journal`, панель виджета, тост |
| `--radius-card-sm` | 10px | мелкое: кадр товара в `#shop`, миниатюра бутика у курсора |
| — | 0 | полноширинные фоновые кадры и видео секций, волосяные линии, разделители, полноэкранная панель меню |

Круглое остаётся круглым: кадры сортов, иконочные кнопки и кнопка виджета —
`50%`, окружность здесь мотив макета, а не ступень шкалы.

Карточки товаров и плитки категорий стоят на `--radius-card-sm`, а не на
`--radius-card`: обе переехали на мелкий формат (карточка витрины стала вдвое
меньше, плитка категории — в одну строку высоты), и 14px на них смотрелись
пухло. Ступень выбирается по размеру предмета, а не по его роли.

Проверено на собранном прототипе: у всех `.btn` и вкладок переключателя
`border-radius` ровно `999px`; полноширинное видео `#hero` — `0px`;
скруглений вне шкалы (произвольных 4px, 6px, 20px) на странице нет.

Золотого кольца ВОКРУГ карточки товара больше нет — приём был рассчитан на
крупную карточку в сетке 3×2, а на карточке вдвое меньше пять колец в ряд
читались бы как рябь. Осталось волосяное золото ПО кадру, проявляющееся на
ховере (`.product__frame::after`). В `#types` кольцо на месте: там круглый
кадр и мотив банки, ради которого приём и заводился.

### Высота секций и ритм

Высоту секции задаёт её содержимое. `min-height: 100svh` (`.section--full`)
остался **только у hero** — 88svh, чтобы край `#trust` выглядывал из-под сгиба.
Это верно для широкой раскладки первого экрана; в узкой (портрет, повёрнутый
телефон) высота hero — по содержимому, см. «Первый экран: ролик бренда».
Раньше полноэкранными были ещё `#types`, `#shop` и `#proof`, и вокруг их
контента набиралось до полутора экранов пустоты.

* `--section-pad` — базовый вертикальный отступ, `clamp(3.25rem, 6.5vh, 6rem)`.
  Сокращён примерно на треть от первой версии (`clamp(5rem, 10vh, 9rem)`).
* `--section-pad-tight` — стык двух секций одной главы. Ставится флагом
  `tight` в `src/data/sections.js`, класс `.section--tight` вешает реестр.
  **Сейчас носителя на основной главной нет:** единственным был `#season`
  после `#shop`, а 16.09.2026 блок снят с основной главной и живёт только
  на `/alt` (там флаг по-прежнему стоит). Флаг и класс в коде оставлены.
* Структурные флаги `full` и `tight` живут в `src/data/sections.js`,
  а не в строках классов сборщиков: в реестре сразу видно устройство страницы.

Что дала правка на 1440×900 (высота страницы 8497 → 7558 px):
`#types` 900 → 667, `#proof` 900 → 687, `#categories` 902 → 839.
Полноэкранных секций, кроме hero, не осталось.

**Коммерческий слой ужат отдельно** — оба блока заказчик назвал самыми слабыми
на показе. Замерено на 1440×900 в headless Chrome, обе сборки подряд:

| Секция | Было | Стало | Чем |
|---|---|---|---|
| `#categories` | 839 | **225** (−73%) | вместо трёх фотоплиток 3:4 — лента плиток со знаками; свои отступы секции, кегль заголовка ниже `--fs-h2`, плитка в одну строку высоты |
| `#shop` | 1652 | **733** (−56%) | один ряд вместо двух, кадр 1:1 вместо 4:5, кегли подписей и переключателя срезаны, кнопка корзины ушла с полосы под фото в угол кадра |

Вся страница: **7529 → 5997 px**, минус экран с лишним.

**Итог последней итерации: 5997 → 6094 px, то есть высота осталась прежней.**
Ужать удалось `#proof` (687 → 587: кегли заголовка и цифр срезаны, отступы
сокращены, композиция не тронута). Но `#offline` вырос с 436 до 510, а вместо
`#delivery` на 441 встал `#why` на 563 — и то и другое потому, что в блоках
стало БОЛЬШЕ содержания: в тексте офлайна появился адрес флагманского бутика,
а доводов стало шесть вместо четырёх пунктов доставки. Большое сокращение
случилось на прошлой итерации (8497 → 7558 → 5997); на этой странице
резервов такого размера уже нет — каждая секция, кроме hero, ниже экрана,
пустых экранов нет ни одного.

Где ещё лежат 126 px, и почему их не срезали, — в «Составе страницы»,
пункт про повтор `#trust` и `#why`.

**Про высоту категорий — второй заход.** Полоса в 225 px была честно
компактной, но заказчик забраковал её по другому основанию: мелкие плитки
в слайдере выглядят дёшево, и листать их никто не станет. Ограничение
«не делать блок сильно высоким» осталось, поэтому решётка 4×2 доведена
до **461 px** на 1440 — вдвое выше прежней полосы и по-прежнему заметно ниже

внутри ячейки пропадает и возвращается «дешёвый» вид) и вертикальных отступах
секции. Менять их надо вместе.

**`#brand` держится под hero отдельно.** Блок информационный, и заказчик просил
явно, чтобы он не читался тяжелее первого экрана. Первая сборка дала 918 px
против 792 px у hero; после правки — 791 px. Держат его три вещи, и трогать их
надо вместе: крупный кадр слева абсолютный и забирает высоту у текстовой

## Навигация

### Карта сайта и страницы

Все адреса сайта перечислены в `src/data/routes.js` — это единственная точка
правды. Оттуда их берут шапка, каталожная панель, подвал и страница
`/sitemap`; по этому же списку `scripts/build-pages.mjs` раскладывает
каркасы `<адрес>/index.html`.

**Ни одной ссылки `href="#"` в прототипе не осталось.** Заказчик кликает
по макету, и мёртвая ссылка читается как поломка, а не как «здесь пока
ничего нет». Каждая ведёт либо на реальный адрес, либо на якорь секции
главной.

```
Коммерческие   /catalog · /catalog/<категория> · /product/<товар> · /gifts
               /corporate · /cart · /checkout · /order-success · /account
               /certificates · /search
Информационные /about · /brands · /production · /documents · /boutiques
               /partners · /wholesale · /journal · /journal/<статья> · /reviews
               /delivery · /returns · /storage · /loyalty · /faq · /contacts
Служебные      /privacy · /terms · /consent · /404 · /sitemap
```

**Семь адресов добавлены вместе с панелью «Компания»** — `/brands`,
`/documents`, `/storage`, `/certificates`, `/loyalty`, `/faq`, `/wholesale`.
Правило прежнее и оно важнее наполнения: раз пункт стоит в панели или
в подвале, у него есть страница. Пусть пока заглушка — но не 404.

Заодно четыре заголовка приведены к формулировкам заказчика из состава
панели: «Возврат и гарантия качества», «Производство и качество»,
«Ресторанам и отелям», «Корпоративные заказы и подарки». Подпись ссылки
и заголовок страницы должны совпадать — иначе человек, перешедший по ссылке,
каждый раз проверяет, туда ли он попал.

Страницы категорий (десять) генерируются из `src/data/catalog.js`, статьи
(три) — из `src/data/journal.js`, **карточки товаров (74) — из
`src/data/catalog-products.js`**: списки не дублируются руками, иначе меню
и карта сайта разойдутся на первой же правке. Всего страниц 141 (22.09.2026:
прибавились витрина `/catalog/ikra`, `/account/waitlist`, 12 карточек
красной икры и коробочная позиция лосося).

**У каждой позиции каталога теперь свой адрес.** Раньше карточка товара была
одна, демонстрационная: слагов у позиций не было. Они есть — 52 позиции
чёрной икры из выгрузки 1С, 12 позиций красной икры по снимку стенда
и 23 демонстрационные позиции рыбы, — и каждая
карточка сетки открывает именно свою страницу. Демонстрационный адрес
(`SAMPLE.product`) остался только для шести позиций витрины главной — пате,
краб, наборы: товарной выгрузки под ними нет вовсе, слаг им придумывать
нельзя, и они ведут на настоящую позицию каталога, то есть на живой шаблон,
а не в никуда.

**В `/sitemap` эти 90 адресов свёрнуты в одну строку** с примером: карта сайта
показывает устройство сайта, а не перечень товаров — семьдесят ссылок подряд
превратили бы её в простыню, в которой не найти ни корзину, ни оформление.

У подкатегорий своих адресов нет. Ссылка ведёт на страницу категории
с фильтром: `/catalog/chernaya-ikra?sub=beluga`. Подкатегория — это фильтр
внутри раздела, а не самостоятельная страница, и плодить под неё адреса
до подтверждения дерева каталога незачем.

**Заглушки.** Внутренние страницы, у которых наполнения ещё нет, собирает
один `src/page.js`: он находит себя в `routes.js` по `location.pathname`
и рисует заголовок, описание того, что здесь будет, и пометку
«страница-заглушка». Дизайна у них нет намеренно — одна колонка на общих
токенах.

Четыре вида страниц собираются иначе, и какой чем — решает `entryFor()`
в `scripts/build-pages.mjs`:

| Что | Точка входа |
|---|---|
| раздел каталога с выгрузкой товаров | `/src/category.js` |
| карточка товара | `/src/product.js` |
| `/cart` · `/checkout` · `/order-success` | `/src/cart.js` · `/src/checkout.js` · `/src/order-success.js` |
| `/sitemap`, `/production`, `/delivery`, разделы без товаров и все прочие | `/src/page.js` |

`/sitemap` — полный список адресов, он же проверка целостности карты (карточки
товара свёрнуты в одну строку); `/production` — единственная заглушка
с готовым текстом, туда переехала секция «Происхождение»; у страниц категорий
без товаров к описанию добавляется список подкатегорий ссылками.

**Как это запускается.** `npm run dev` и `npm run build` сами вызывают
генератор (`predev` / `prebuild`), отдельно — `npm run pages`. Каркасы
помечены в первой строке `<!-- GENERATED … -->`: править их бессмысленно,
при следующем запуске затрутся, а исчезнувшие из карты сайта — удалятся.
Список входных html для сборки `vite.config.js` собирает обходом файлов,
а не руками: сто с лишним строк в конфиге — сто с лишним шансов забыть одну
и получить 404 в собранной версии.

⚠ **Удаление каркасов на этой машине не срабатывает.** Генератор честно
находит папки, исчезнувшие из карты сайта, рапортует «удалено лишних: N»,
но `fs.rmSync` на диске OneDrive их не убирает — и на следующем запуске
находит те же. Пока папка не удалена руками, она попадает в сборку
и остаётся живым адресом. Если после правки карты сайта в `dist` остался
лишний адрес — удалить папку вручную.

Там же лежит middleware `prettyUrls`: адреса открываются как `/catalog`,
без хвостового слеша и без `.html`, а несуществующий адрес показывает
страницу `/404`. Работает и в `dev`, и в `preview`.

### Шапка

Заказчик просил разгруженный верх; референс по разгруженности — «Заморская
лавка»: наверху минимум надписей, богатство ассортимента раскрывается внутри
панелей.

```
полоса   Доставка и оплата · Бутики · Контакты      +7 925 466 66 46 · Мессенджеры ⌄
шапка    [КАТАЛОГ ⌄] ИКРА ПОДАРКИ   логотип   КОМПАНИЯ ⌄ [🔍 Поиск по каталогу] ♡ ☺ 🛒²
```

В полосе — операционные вопросы, ответ на которые человек должен видеть без
единого клика: как доедет, где купить руками, куда звонить. **Селектора
региона в шапке нет и не будет** — заказчик отказался явно; города живут
на странице бутиков и в блоке «Офлайн» на главной.

**«О БРЕНДЕ» стало «КОМПАНИЯ».** Пункт вёл на одну страницу `/about` и рядом
с товарными читался как ещё одна страница о себе — заказчик справедливо
опасался, что за ним не станут искать доставку, возврат или документы. Теперь
это вход во все информационные страницы сайта. Название вынесено отдельным
значением (`navCompany.label` в `src/data/nav.js`): заказчик может захотеть
«О нас» или «Информация», и это не должно требовать правок в разметке.

**Текстовых пунктов ровно четыре, и это ограничение.** Пятый добавлять нельзя:
всё остальное живёт внутри панелей и в подвале. Если раздел «просится» в
шапку — ему место в панели «Компания», в каталожной панели или в подвале.

**Шеврон — обещание, а не украшение.** Пункты, ведущие на страницу, и пункты,
раскрывающие панель, выглядели одинаково, и это была главная причина, по
которой панель могли не найти. Теперь у раскрывающихся рядом со словом стоит
шеврон, при открытии он разворачивается на 180°.

Ставится он **только там, где панель действительно есть**, и вопрос «есть ли»
задаётся реестру сборщиков (`hasPanel` из `nav/panels.js`), а не полю `panel`
в данных. Разница принципиальная: поле в данных — заявка на будущую панель,
шеврон — обещание, что панель откроется прямо сейчас. Шеврон над обычной
ссылкой обманывает ровно тем способом, от которого просили избавиться.

⚠ **Поэтому у «Икры» и «Подарков» шеврона сейчас НЕТ**: панелей у них
не собрано, и это единственное расхождение с заказанным составом. Появится
сборщик — шеврон возникнет сам, без правок в шапке.

**Избранное и аккаунт — рабочие страницы** (17.09.2026). У избранного свой
адрес `/favorites`: оно работает и без входа, поэтому вкладкой кабинета быть
не может; прежний `/account?tab=favorites` убран отовсюду. У сердца счётчик
того же вида, что у корзины, скрыт при нуле. Человек у гостя ведёт на
`/account/login` (подпись «Войти»), у вошедшего — на `/account` («Личный
кабинет, {имя}»); у вошедшего с именем вместо иконки стоит круг 30px с первой
буквой имени шрифтом Prata. Уже 1024px обе иконки скрыты селектором по адресу
(`a[href^="/account"]`, `a[href^="/favorites"]` — серверная шапка Битрикса рисует
ссылки без классов), а в мобильном меню те же две ссылки меняют текст:
«Войти» или «{Имя} · кабинет», «Избранное» или «Избранное · {n}». При
`initHeader({ ssr: true })` шапка состояние входа и счётчик избранного не
трогает вовсе — на Битриксе их отдаёт сервер. Подробности — «Личный кабинет,
вход и избранное».

### Поиск — капсула, а не лупа

Заказчик просил выделить поиск явно, возможно словом. Пятым текстовым пунктом
меню слово «Поиск» стоять не может — ограничение выше по разделу и оно
не отменяется. Но поиск и не раздел: это инструмент, и оформлен он как
инструмент — компактная капсула, стилизованная под поле.

* капсула на волосяной линии, высота как у «Каталога» (40 px), слева лупа,
  дальше приглушённая подпись «Поиск по каталогу». Заливки нет, скругление
  капсульное;
* приём осмысленный, а не декоративный: слева капсула «Каталог» — вход
  в ассортимент, справа капсула «Поиск» — вход в поиск, между ними логотип.
  Две капсулы держат шапку симметрично;
* это по-прежнему `<button>` с `data-search-trigger`, `aria-haspopup="dialog"`
  и подписью для скринридера. Механика раскрытия строки (`nav/search.js`)
  не тронута вовсе — сменилась только точка входа. Настоящий `<input>` здесь
  стоять не может: по нажатию поле разворачивается во всю ширину шапки,
  и два поля подряд читались бы как подмена.

Три ширины, три подписи, и все три лежат в `navSearch` (`src/data/nav.js`),
а не в разметке:

| Ширина | Что видно |
|---|---|
| ≥ 1280 | капсула с полным текстом «Поиск по каталогу» |
| 1024–1279 | капсула сжимается до лупы и слова «Поиск» |
| < 1024 | иконка, открывающая полноэкранный слой — как было |

**Логотип от этого не сдвинулся.** Правая группа потяжелела, поэтому боковые
колонки шапки переведены с `1fr` на `minmax(0, 1fr)`: у `1fr` минимум равен
содержимому, и более тяжёлая правая группа отжимала бы логотип из центра.
Замерено на 1280, 1440 и 1600 — отклонение центра логотипа от центра
контейнера 0 px на всех трёх. Ширина капсулы при этом вилка
`clamp(11.5rem, 14vw, 13.125rem)`, а не жёсткие 210 px: единственный тесный
случай — 1280, где при 210 px между «КОМПАНИЕЙ» и логотипом оставалось 7 px;
с вилкой там 33 px.

### Мессенджеры в верхней полосе

Вместо одной ссылки на WhatsApp в полосе стоит пункт «Мессенджеры»
с маленьким поповером: WhatsApp и Telegram, оба адреса из `contacts`.

Пункт — настоящая ссылка на `/contacts`, а не кнопка: без JS и на мобильном,
где полоса сжимается до телефона, он обязан куда-то приводить. На десктопе
клик перехватывается и раскрывает список. Закрытие — повторное нажатие, `Esc`,
клик вне и уход фокуса; `aria-expanded`, `aria-haspopup="menu"`, стрелки ходят
по пунктам. Оформление — волосяная линия и `--surface`, без тени.

В мобильном меню обе ссылки тоже есть, и берутся они из тех же данных, а не
пишутся строкой в разметке.

«Каталог» оформлен капсулой с тремя линиями — единственный элемент шапки
с рамкой, и потому читается как кнопка, а не как ещё один пункт меню.
У бургера мобильного меню линии две, а не три: два разных знака для двух
разных действий.

Ссылка у капсулы настоящая (`/catalog`) — это нужно поисковику, мобильному
и клавиатуре без JS. На десктопе клик по ней перехватывается и открывает
панель; уйти в раздел можно из самой панели, там есть «Открыть весь каталог».

Плотное состояние шапки складывается из двух причин — ушёл hero **или**
открыта панель. Полупрозрачная шапка поверх раскрытой панели выглядит грязно.
Обе причины сведены в `applyHeaderSkin()` (`src/js/sections/header.js`),
иначе они перетирали бы друг друга.

### Выпадающие панели (`src/js/nav/`)

Панели могли бы открываться у четырёх пунктов: КАТАЛОГ, ИКРА, ПОДАРКИ,
КОМПАНИЯ. **Сейчас собраны две — каталожная и «Компания»**, у «Икры»
и «Подарков» сборщика пока нет. Пункт без сборщика остаётся обычной ссылкой,
работает как ссылка и не получает шеврона: добавить панель — это положить
`build` / `init` в `src/js/nav/panels.js` под тем же ключом, что стоит
в поле `panel` у пункта в `src/data/nav.js`. «Икра» с 22.09.2026 ведёт
на общую страницу `/catalog/ikra` (см. «Витрины» в разделе «Каталог:
страница категории»).

Поведение (`megamenu.js`):

* **открытие по наведению с задержкой 140 мс** — панель не должна выскакивать,
  когда курсор просто прошёл по шапке к логотипу;
* **закрытие с задержкой 260 мс** — за это время курсор успевает уйти с пункта
  в панель по диагонали. Если панель уже открыта, соседняя открывается без
  паузы: при быстром переборе пунктов мигания нет;
* **клик мышью никогда не закрывает панель** (22.09.2026). Человек наводит
  курсор на «Каталог» и сразу нажимает: наведение успевало открыть панель,
  а клик её тут же закрывал, и каталог выглядел неоткрывающимся. Теперь клик
  по закрытому пункту открывает панель сразу (отложенное открытие по
  наведению отменяется), клик по открытому — ничего не делает, двойной клик
  тоже. Закрывается панель уводом курсора, Esc, кликом мимо шапки, прокруткой
  и переходом по ссылке в панели;
* **клавиатура и касание переключают**: Enter (клик с `event.detail === 0`)
  открывает и закрывает, ↓ открывает и ставит фокус на первую категорию,
  Esc закрывает и возвращает фокус на пункт. На устройствах без наведения
  шире 1024px (планшет горизонтально) касание тоже переключает — закрыть
  панель там иначе нечем, кроме касания мимо;
* **фокус не убегает**: пока панель открыта, Tab ходит по кругу «пункт →
  панель → пункт». Иначе фокус уезжает на страницу под затемнением и человек
  табает вслепую;
* одновременно открыта только одна панель; **прокрутка закрывает** (сравниваем
  позицию, а не ловим событие: браузер шлёт `scroll` и когда подкручивает
  страницу к элементу с фокусом);
* **панель и поиск гасят друг друга**: строка поиска занимает место содержимого
  шапки, и оставшаяся под ней раскрытая панель висела бы непонятно от чего;
* страница под панелью притеняется (`.nav-scrim`, z-index 75 — ниже шапки,
  выше кольца прогресса); виджет эксперта живёт над затемнением и гасится
  отдельно, через `filter`;
* **на мобильном панелей нет вовсе** — ниже 1024px там своё меню.

Раскрытие — `clip-path` сверху вниз плюс лёгкий подъём содержимого, 360/420 мс.
Не «щелчок» с opacity: панель разворачивается как штора — тот же приём, что
у входа секций на главной.

### Каталожная панель

Категорий будет много, и сколько именно — пока неизвестно. Плоский список
в шапку не помещается, поэтому вход в ассортимент единый, а выбор категории
уже внутри панели. Композиционный ориентир — панель «SMOKED FISH & SEA»
у Petrossian: слева простой список, справа крупные карточки с картинками.

```
┌──────────────┬────────────────────────────────────┬─────────────┐
│ Чёрная икра  │  [фото] [фото] [фото] [фото]       │  [Хиты      │
│ Красная икра │  [фото] [фото] [фото] [фото]       │   продаж]   │
│ Рыба         │                                     │             │
│ …            │  Все товары раздела «Чёрная икра»  │  [Новинки   │
│ Новинки      │                                     │   сезона]   │
├──────────────┴────────────────────────────────────┴─────────────┤
│ [ОТКРЫТЬ ВЕСЬ КАТАЛОГ →]        Новинки · Подарочные наборы     │
└──────────────────────────────────────────────────────────────────┘
```

Колонок с фильтрами по вкусу и грейду здесь нет намеренно: такой вариант
(каверная панель Petrossian) заказчиком отклонён.

**По умолчанию открыта чёрная икра** — флагманский продукт встречает первым,
до того как курсор дошёл до списка. Каждое открытие панели возвращает её же.

Три вещи, которые в этой панели важнее красоты:

1. **Все пункты — настоящие ссылки.** Ни одного «пункта», который оживает
   скриптом: разметка индексируется как есть.
2. **Высота не прыгает при переборе категорий.** Все зоны подкатегорий лежат
   в одной ячейке грида друг на друге, поэтому высота панели равна самой
   высокой из них. Скрытые — `visibility: hidden`, а не `display: none`:
   так они выпадают из табуляции, но продолжают держать высоту. Проверено:
   после перехода на реальное дерево категорий десять, панель 540 px
   при 1440×900 и 1366×768.

   Исключение одно: у разделов **без подкатегорий** (крабы и морепродукты,
   подарочные наборы — подразделов в 1С у них нет) вместо сетки стоит
   описание раздела. Пустая правая зона читается как несобравшаяся панель,
   а описание высоту не колеблет: оно выводится только там, где карточек
   нет вовсе.
   По той же причине в панели нет описаний категорий, хотя в данных они есть
   и стоят на страницах разделов: строка описания у одних категорий умещается
   в строку, у других переносится, и сетка карточек съезжала бы вниз.
   Ссылка «Все товары раздела» прижата к низу зоны — иначе она гуляла бы
   между сетками из шести и восьми карточек.
3. **Панель не выше двух третей экрана** и не перекрывает логотип: она
   прикреплена к нижнему краю шапки, `max-height: min(66vh, …)`, внутри
   свой скролл на случай очень длинного списка. Высота строки категории
   считается от высоты экрана (`clamp(32px, 4.2vh, 40px)`): на ноутбуке 768px
   одиннадцать строк по 38 px вместе с нижней строкой панели не помещались.
   Реальных категорий десять, то есть запас к прежнему ограничению есть.

Карточки подкатегорий берут кадры из `/media/nav/<категория>-<подкатегория>.jpg`
и работают без файлов: на месте кадра рисуется заглушка с именем и пропорцией,
как во всех остальных секциях. Что именно снимать — в `public/media/README.md`,
раздел `nav/`.

### Панель «Компания»

Информационный хаб: три колонки текстовых ссылок и один кадр справа.
Состав — `src/data/company.js`, сборка — `src/js/nav/company-panel.js`.

```
ПОКУПАТЕЛЯМ            КОМПАНИЯ                    СОТРУДНИЧЕСТВО      [кадр]
Доставка и оплата      О компании                  Ресторанам и отелям
Возврат и гарантия     Наши бренды                 Корпоративные заказы
Как хранить и подавать Производство и качество     Оптовым покупателям
Подарочные сертификаты Документы и сертификаты
Программа лояльности   Бутики и представительства
Вопросы и ответы       Отзывы
                       Контакты
```

**Порядок колонок зафиксирован заказчиком и значим**: сначала «Покупателям»,
потом «Компания», потом «Сотрудничество» — от пользы посетителю к рассказу
о себе. Обратный порядок («сначала о нас») — самая частая ошибка таких
панелей: человек пришёл с вопросом о доставке, а первое, что ему предлагают,
это история компании.

**Почему текст, а не карточки с фотографиями.** В каталожной панели карточки
уместны: там выбирают товар глазами. Здесь ищут конкретный ответ — «как
вернуть», «где документы», — и кадр рядом с каждой ссылкой только замедляет
чтение. Один кадр на всю панель оставлен, чтобы она не выглядела списком
из служебного меню; он же ведёт на `/about`.

Заголовки колонок — надзаголовки, принятые на сайте (мелкие прописные
с разрядкой, золотые), но тегом `<h3>`: оформление даёт класс `.eyebrow`,
а иерархию — тег, по нему скринридер прыгает внутри панели.

**Ссылки «Журнал» здесь нет намеренно.** Журнал не информационная страница
о компании, а отдельная сущность со своей лентой: он живёт на главной
и в подвале.

Своей механики у панели нет — она статична, всё поведение (наведение, клик,
Esc, кольцо фокуса) приходит из общего `megamenu.js`.

### Поиск в шапке (`src/js/nav/search.js`)

По нажатию на капсулу поиска (на мобильном — на иконку) содержимое шапки
гаснет, и **на его месте, в той же высоте**, разворачивается строка поиска
во всю ширину. Под шапкой раскрывается
панель подсказок.

**Почему во всю ширину, а не полоской справа.** Логотип стоит по центру шапки.
Строка на половину ширины либо упирается в него, либо заставляет его съезжать
вбок — и то и другое читается как поломка. Замена всего содержимого решает
сразу и это, и вопрос места: строке достаётся вся ширина, а панели подсказок —
вся ширина под шапкой.

**Высота шапки не меняется, логотип не прыгает.** Строка лежит абсолютом
внутри `.header > .container`, а `.header__inner` никуда не девается — он
только гаснет (`opacity` + `visibility`) и уходит на 6 px вверх трансформом.
Если бы его убирали через `display: none`, высоту держать было бы нечему
и шапка схлопывалась бы на все 76 px. Проверено замером: 77 px до раскрытия
и 77 px после, позиция логотипа в потоке та же.

Три состояния панели:

* **пустое поле** — последние запросы, популярные запросы, недавно
  просмотренные товары;
* **есть ввод** — товары с миниатюрой, названием и ценой и подсветкой
  совпадения; отдельным разделом совпавшие разделы каталога; внизу строка
  «Показать все результаты» с числом;
* **нет совпадений** — объяснение и выход в каталог.

**Клавиатура.** ↑/↓ ходят по строкам выдачи, Enter уходит по выделенной строке
(или на `/search?q=…`, если ничего не выделено), Esc закрывает, клик мимо
шапки закрывает. Роли `combobox` / `listbox` расставлены на поле и на списке.
Кольца фокуса здесь нет намеренно, в отличие от мегапанелей: уход табом
за пределы шапки просто закрывает поиск и не возвращает фокус назад — это
поведение обычного комбобокса, из поиска человек чаще уходит дальше
по странице, чем по кругу между полем и подсказками.

**Мобильный — отдельный слой.** В шапке шириной 360 px строка с крестиком
и кнопкой отмены не помещается рядом ни с чем, а панель подсказок под ней
всё равно занимает весь экран. Ниже 1024 px поиск открывается полноэкранным
слоем — тем же движением снизу вверх, что и мобильное меню, чтобы два
полноэкранных слоя сайта вели себя одинаково. Прокрутка страницы под слоем
блокируется в двух местах: нативная (`body.is-locked`) и Lenis (`lenis.stop()`).

⚠ **Настоящего поиска в прототипе нет и не должно быть.** Совпадение
подстрокой по уже имеющемуся набору товаров (`catalog-products.js`) и по
дереву каталога, плюс список синонимов разделов: человек ищет «осетр», а
позиция называется «Икра осетровая». Последние и популярные запросы, а также
«недавно смотрели» — **вымышленные**: на живом сайте это localStorage
и статистика поиска. Подробности и что чем заменить — в шапке
`src/data/search.js`.

### Подвал — полный указатель

Заметная часть людей ищет служебные страницы внизу, а не вверху. Поэтому
подвал перестал быть коротким набором «главного»: пять групп по смыслу —
**каталог, покупателям, компания, сотрудничество, контакты** — и правовая
строка снизу: политика конфиденциальности, публичная оферта, согласие
на обработку персональных данных, карта сайта.

Каталожная колонка **собирается из `src/data/catalog.js`**, а не ведётся
руками: иначе она разойдётся с каталогом на первой же правке и в подвале
появятся ссылки на несуществующие разделы.

Чего в подвале нет и почему: `/checkout` и `/order-success` (шаги оформления,
в них приходят из корзины), `/search` (не страница, а результат действия),
`/404` (недостижима ссылкой), `/product/<слаг>` и `/journal/<слаг>` (шаблоны,
а не разделы). Всё это всё равно доступно из `/sitemap`, ссылка на карту
стоит в правовой строке.

Брендовый блок ушёл строкой выше указателя: колонок стало пять, и на него
оставалось около 150 px — тэглайн ломался в столбик по два слова.

## Скролл-движок (`src/js/scroll.js`)

Заказчик формулирует так: «мягкая анимация как по слайдам сменяющимся».

| Что | Как |
|---|---|
| Инерция | Lenis: duration 1.35, wheelMultiplier 0.9, smoothWheel, без syncTouch |
| Вход секции | clip-path `inset(12% 0 0 0)` → `inset(0)`, медиа-слой 1.045 → 1, контент stagger fade-up 0.07. Триггер `top 82%`, `power3.out`, 1.1 с |
| Уход и параллакс hero | слой на −6% и в 0.55, видео вниз на 12%, контент вперёд слоя — по scrub от `top top`. Живёт в `js/sections/hero.js` |

Анимируются только `transform`, `opacity` и `clip-path`.

### Чего в движке нет и почему

**Доводчика к границам секций больше нет.** Он имел смысл, пока секции были во
весь экран: их границы совпадали с границами кадра. Теперь высоту секции задаёт
её содержимое (см. «Высота секций и ритм»), доводить не к чему, а подтягивание
после остановки читается как то, что страница вырывается из рук. Функция
`createSnap()` и флаг `SNAP_ENABLED` удалены целиком — гасить нечего.

**Общего ухода у остальных секций тоже нет.** Он отсчитывался от `bottom bottom`,
то есть от момента, когда низ секции доходит до низа экрана. У секции ниже
экрана этот момент наступает, пока она ещё целиком в кадре, — контент гаснул
прямо во время чтения. У hero, который остался полноэкранным, уход свой
и отсчитывается от `top top`.

Уход применяется к `.section__layer`, а не к самой секции: фон остаётся
на `.section`, поэтому между секциями не появляется полосы чужого цвета.

### Кольцо прогресса

Левый нижний угол (правый занят виджетом эксперта). Показывает долю
прочитанного, номер текущей остановки и её название — подпись меняется с fade.

Остановок девять, а секций одиннадцать. Полей `ring` нет у двух: `#trust` —
узкая полоса под первым экраном, самостоятельной остановкой она не читается
и относится к «01 Начало»; `#season` продолжает главу витрины и наследует
её остановку. Название остановки задаётся полем `ring`
в `src/data/sections.js`; секция без `ring` наследует номер и подпись
предыдущей.

```
01 Начало · 02 Виды икры · 03 Ассортимент · 04 О бренде · 05 Доверие
06 Витрина · 07 Офлайн · 08 Стандарт · 09 Журнал
```

## Плавающий виджет «Подобрать с экспертом»

Правый нижний угол, отступ 24px (16px на мобильном). Появляется после первого
экрана, исчезает на подвале. Свёрнут — круглая кнопка 56px с золотой иконкой
диалога; при наведении слева выезжает плашка.

**Главное действие — форма, а не мессенджер.** Заказчик просил, чтобы писать
можно было прямо с сайта: уход в WhatsApp это выход со страницы, и часть людей
туда просто не пойдёт. По клику снизу вверх раскрывается панель **380 px**
(было 280): заголовок и подзаголовок прежние — их заказчик просил не трогать, —
дальше форма:

| Поле | Обязательное |
|---|---|
| Имя | нет |
| Телефон или ник в мессенджере | **да** |
| Сообщение, три строки | нет |
| Согласие на обработку персональных данных со ссылкой на `/consent` | **да** |

Одно поле на телефон и ник намеренно: человек пишет туда, где ему удобно
отвечать, и заставлять его выбирать формат — лишний шаг.

⚠ **БЭКЕНДА НЕТ.** Отправка перехватывается, форма подменяется состоянием
успеха внутри той же панели: «Спасибо, менеджер напишет в течение 15 минут»
и кнопка «Написать ещё». Ни запроса на сервер, ни его имитации, ни выдуманного
номера заявки. Что нужно сделать на живом сайте: подключить приём заявок
(почта, CRM или мессенджер менеджера) и проверить текст согласия — **без
согласия форму с телефоном на российском сайте публиковать нельзя**, поэтому
кнопка отправки заблокирована, пока чекбокс не отмечен.

Мессенджеры остались, но стали вторичными: одной приглушённой строкой под
формой — «или напишите в WhatsApp · Telegram». Телефон остался внизу.

Валидация проверяет только обязательное: сообщения об ошибках стоят под
полем, а не всплывают, и первое поле с ошибкой получает фокус. При открытии
фокус уходит на первое поле — панель открыли, чтобы писать, а не чтобы искать,
куда нажать.

Закрывается крестиком, по Esc и по клику вне панели — из любого состояния,
включая экран успеха. Пока панель открыта, фокус заперт внутри неё (поля тоже
в круге), после закрытия возвращается на кнопку.

Виджет открывается и снаружи: кнопка «Спросить эксперта» на карточке товара
шлёт событие `expert:open`. Заводить на карточке вторую такую же форму значило
бы удвоить точку приёма заявок.

Отдельной секции в потоке страницы и дублирующего блока нет — так просил
заказчик. Тексты — в `src/data/expert.js`.

## Медиа-заглушки (`src/js/media.js`)

Прототип полностью работает без единого медиафайла — это проверено отдельным
прогоном с пустой `/public/media`: вёрстка не разъезжается, высота страницы
меняется на два пикселя.

Каждое изображение и видео заводится через обёртку: путь + пропорция.
Пропорция держится через `aspect-ratio` на обёртке и через атрибуты
`width`/`height` на самом `<img>`, поэтому места под кадр зарезервировано
столько же, сколько займёт файл.

Если файл не загрузился — на его месте фон `--surface`, тонкая золотая рамка и
моноширинная подпись вида `caviar-beluga.jpg · 1:1`. У видео всегда есть постер;
если нет ни ролика, ни постера — заглушка со статичным затемнением.

Единственное исключение по `width`/`height` — логотип: его настоящая пропорция
неизвестна, пока файла нет, а неверная подсказка хуже отсутствующей. Логотип
стоит в средней ячейке сетки `1fr auto 1fr`, поэтому его загрузка ничего
не сдвигает.

## Доступность

* **`prefers-reduced-motion: reduce`** — Lenis не поднимается, доводчик выключен,
  бегущая строка партнёров останавливается и отдаётся нативному скроллу,
  параллакс hero не создаётся, видео не автоплеится, отсчёт цифр
  не запускается, все reveal сразу в конечном состоянии.
* **Фокус виден везде**: `:focus-visible` — обводка `--caspian` 2px с отступом 3px.
  Порядок табуляции линейный; в карточках товара и журнала один табстоп на
  карточку, дубли из потока убраны.
* **Селектор «Себе / В подарок»** — полноценный `tablist`: `role="tab"` с
  `aria-selected` и roving `tabindex`, `role="tabpanel"` с `aria-labelledby`,
  стрелки влево-вправо, Home и End.
* **Контраст текста не ниже 4.5:1** во всех состояниях обеих тем. Ради этого
  введены `--gold-fg` / `--caspian-fg` (см. «Токены») и поднята непрозрачность
  переключателя темы в подвале.
* Зона касания интерактивных элементов — не меньше 44px по высоте.
* Кольцо прогресса помечено `aria-hidden`: это дублирующий индикатор.

## Производительность

* `loading="lazy"` и `decoding="async"` на всех изображениях; первый экран —
  видео с постером, не картинка.
* `width` и `height` на всех `<img>` — сдвига макета при загрузке нет.
* `will-change` ставится только на время анимации и снимается в `onComplete`
  или в `onToggle` триггера (`markMoving()` в `scroll.js`). Постоянных
  композиторных слоёв на секциях нет.
* Hero-видео не грузится вовсе при включённом Data Saver и на 2G/slow-2g
  (`canLoadVideo()` в `media.js`) — остаётся постер. Ролик играет только
  пока он в кадре.

## Мобильная ревизия

Проверено на 360, 390, 768, 1024, 1280, 1440 и 1600: горизонтального
переполнения нет ни на одной ширине ни на одной из проверенных страниц
(главная, раздел каталога, карточка товара, статья, бутики, карта сайта),
консоль чистая — кроме 404 на ещё не присланные медиафайлы.

Отдельно на 390px и 360px:

* горизонтального переполнения нет — `scrollWidth === clientWidth`;
* горизонтальные ленты (`#types`, `#shop`) скроллятся пальцем и не
  перехватывают вертикаль: `touch-action` у обеих — `auto` (проверено
  в собранном прототипе на 390 и 360), драг мышью не эмулируем, Lenis ведёт
  только вертикаль (`syncTouch: false`). Исключение одно и намеренное:
  у дорожки ползунка витрины `touch-action: none` — иначе протяжка ползунка
  пальцем листала бы страницу вместо ленты;
* решётка `#categories` на планшете идёт в 4 колонки, ниже 768px — в 2,
  ниже 420px — в одну, и ячейка там раскладывается в строку (знак слева,
  название, счётчик справа). Тройки колонок нет намеренно: восемь ячеек
  в три колонки дают дырку в последнем ряду, а дырка в решётке из сплошных
  линий читается как поломка вёрстки;
* при эмуляции тач-устройства (`hover: none`, `pointer: coarse`) пейджер лент
  скрыт, полоса позиции на месте, кнопка «в корзину» показана всегда,
  миниатюра бутика не строится вовсе;
* `#why` ниже 900px превращается из разворота в аккордеон: заголовки видны
  все шесть, первый раскрыт; `#season` ниже 1024px теряет окно предпросмотра
  и получает миниатюры 56×56 в строках, а ниже 420px цена уезжает под текст;
  список городов `#offline` идёт одной колонкой, цифры `#proof` — 2×2;
* карточка товара ниже 1024px складывает верхний разворот в одну колонку,
  ниже 768px характеристики идут одной колонкой, а пейджер над лентами
  прячется: пальцем ленты листаются сами;
* панель виджета эксперта ниже 768px считает позицию от края экрана, а не
  от кнопки: она шире кнопки и иначе уезжала бы за край. Внутри свой скролл —
  на телефоне клавиатура съедает нижнюю половину экрана;
* **поиск открывается полноэкранным слоем**, а не строкой в шапке: ниже
  1024px рядом с логотипом и корзиной строке остаётся полторы сотни
  пикселей. Слой приходит снизу вверх, как мобильное меню, и так же
  блокирует прокрутку под собой;
* **в мобильном меню три информационные колонки** («Покупателям», «Компания»,
  «Сотрудничество») под крупными строками разделов: выпадающих панелей
  на мобильном нет, и без этого блока содержимое «Компании» было бы доступно
  только из подвала. Ниже 480px колонки складываются в одну;
* на тач-устройствах пейджер витрины и стрелки поверх краёв скрыты совсем
  (`@media (hover: none)`), а ползунок остаётся — без кнопок он единственный
  явный знак того, что лента длиннее экрана, и его же можно тянуть пальцем;
* кнопки и ссылки — минимум 44px по высоте касания;
* открытое меню блокирует и нативный скролл (`body.is-locked`), и Lenis
  (`lenis.stop()`): одного мало, инерция живёт своей прокруткой.

### Как устроена секция

| Файл | Что в нём |
|---|---|
| `src/data/<тема>.js` | финальные тексты и данные |
| `src/js/sections/<id>.js` | `build<Id>()` — разметка, `init<Id>()` — свои анимации |
| `src/styles/sections/<id>.css` | стили секции |

Сборка идёт в две фазы: `renderSections()` строит DOM до подъёма скролл-движка,
`initSections()` вешает анимации **после** `initScroll()`. Реестр — в
`src/js/sections/index.js`.

### Что стоит знать по отдельным секциям

- **#hero** — единственная секция с привязкой к экрану, и только в широкой
  раскладке: 88svh, а не 100svh, край `#trust` намеренно виден при загрузке.
  В узкой раскладке высота по содержимому. Вход — своя таймлиния, поэтому
  `data-reveal` у секции нет. Уход и параллакс — тоже свои, от `top top`:
  у секции ниже экрана низ доходит до низа кадра ещё при нулевой прокрутке.
  Альтернативные H1 лежат комментарием рядом с заголовком. Раскладки, зона
  логотипа и затемнение — в разделе «Первый экран: ролик бренда» ниже.

  **Про обрезанные строки H1.** Строки заголовка выезжают из-под маски
  clip-path, а clip-path режет строго по боксу элемента. Бокс строки при
  `--lh-h1: 1.05` на пару пикселей уже реальных глифов Prata, и у второй
  строки срезало хвост «р» и верх цифр «300» — заказчик заметил это первым.
  Шрифт ни при чём: там, где clip-path нет, те же глифы рисуются целиком.
  Лечится вертикальным `padding` у `.hero__line`, скомпенсированным
  отрицательным `margin`: бокс для маски выше, межстрочный ритм прежний —
  у inline-block высоту строки задаёт margin-бокс.
- **#brand** — асимметричный коллаж 5/7 по мотиву блока о компании на
  действующем сайте: слева крупный вертикальный кадр с курсивной врезкой,
  справа текст, факты, ссылка и два меньших кадра разного формата. Своего
  `init` у секции нет — вход идёт общим reveal, крупный кадр помечен
  `data-reveal-media`. Про высоту см. «Высота секций и ритм»: она держится
  на трёх настройках сразу.
- **#categories** — не витрина, а указатель. **Восемь** разделов решёткой 4×2,
  целиком на одном экране: прокрутки нет вовсе. До этого здесь была лента
  на двенадцать мелких плиток, и заказчик забраковал её дважды справедливо —
  плитка с восьмипиксельной цифрой выглядит дёшево, а горизонтальную ленту
  в служебном блоке никто не листает: пять разделов из двенадцати не видел
  никто. После выгрузки из 1С восемь ячеек — это **весь каталог без икры**,
  ровно по одной на раздел верхнего уровня: ничего не выбрано произвольно
  и ничего не потеряно (ради этого мелкие разделы 1С и укрупнены). Икры
  в блоке нет по названию секции — она в шапке, в панели и в подвале.
  Решётка 4×2 держится ровно на восьми; девятая ячейка оставит в ряду
  три дырки. Решётка собрана волосяными линиями, а не рамками вокруг
  каждой ячейки: `gap: 1px` показывает фон-подложку — это и убирает «дешёвый»
  вид, рамки с радиусами вокруг мелких элементов всегда читаются как чужой
  набор компонентов. Название набрано антиквой (`--font-display`), а не
  гротеском: в ленте оно было подписью к иконке, в решётке — заголовком
  ячейки. Счётчик пишется словами («230 позиций»), числа настоящие,
  из выгрузки; подпорка в `aria-label`
  больше не нужна. Знак подрос с 24 до 30 px, рисунки те же —
  `src/js/icons.js`, набор `cat*`, волосяная линия 1.25, как в полосе доверия.
  Своего `init` у секции нет: вход — общий reveal, ховер — CSS.
- **#types** — шапка идёт общим reveal, ряд кругов — своим каскадом слева
  направо. Заголовок сменился: было «Четыре вида. Девять линеек.» — он
  пересказывал картинку (четыре круга и так перед глазами), а число линеек
  покупателю ничего не даёт, это внутренняя учётная величина. Стало
  «У каждого вида — свой характер»: заголовок даёт причину рассмотреть круги
  и подводит к подписи под ним — «Отличается зерно, плотность и вкус, но не
  происхождение». Запасные варианты лежат комментарием рядом.
- **#shop** — короткая витрина-подсказка, а не каталог: на десктопе видно пять
  карточек и краешек шестой, остальные прокручиваются. Заливка активной вкладки
  не мигает, а переезжает отдельной подложкой; радиус капсулы стоит и на рамке,
  и на заливке, иначе она вылезает углами. При смене набора фазы ухода и прихода
  перекрываются, а высота контейнера зафиксирована, чтобы страницу не дёргало;
  лента после смены пересчитывает края — наборы разной длины. «В корзину» —
  иконочная кнопка в углу кадра, появляется по наведению; на тач-устройствах
  показана всегда. Названия товаров сверены с кадрами: подписи и фотографии
  должны совпадать хотя бы по смыслу.

### Первый экран: ролик бренда

17.09.2026 в первом экране стоит ролик бренда с действующего сайта
grandgurme.ru — нарезка производства (разделка, посол, копчение), упаковка
№1 Caviar и Siberian Luxury Bar, в финале всплеск воды и золотой логотип
«№1 ГРАНД ГУРМЭ» по центру кадра. Ролик идёт по кругу, 20,3 с. Прежний ролик
с банкой икры (`hero-caviar*`) удалён. Откуда файлы и как они сделаны —
в шапке записи `video.hero` в `src/data/media.js`.

**Зона логотипа.** В горизонтальном файле логотип занимает 31–69 % ширины
и 38–60 % высоты («№1» — 38–47 %, надпись — 53–60 %). Зона — логотип с запасом
3 % с каждой стороны. Текст и кнопки в неё не заходят ни на одном экране:

| Что на экране | По горизонтали | По вертикали |
|---|---|---|
| горизонтальный файл, кадр 16:9 без обрезки | 28–72 % | 35–63 % |
| горизонтальный файл в квадратном кадре (`cover`) | 13–87 % | 35–63 % |
| вертикальный файл 4:5 | 5–95 % | 35–63 % |
| широкая раскладка (`cover` по размеру секции) | считается по размеру `<video>` из 28–72 % × 35–63 % исходника | |

В широкой раскладке кадр выше секции (124 %), поэтому на экране зона лежит
на 31–66 % высоты секции, а низ самого логотипа — на 38 % высоты от нижнего
края. От этого считается всё остальное: затемнение под текстом обязано стать
прозрачным ниже логотипа, а блок текста — уложиться под зоной.

**Две раскладки.** Граница — медиазапрос
`(orientation: landscape) and (min-width: 768px) and (min-height: 600px)`,
один и тот же в `hero.css` и в `hero.js` (константа `WIDE`).

* **Широкая.** Видео во всю секцию, 88svh. Центр кадра свободен, текст собран
  в полосу у нижнего края: `.hero__content` — сетка из 12 колонок,
  `.hero__heading` (надзаголовок и H1) в колонках 1–8, кнопки от 1280px —
  в колонках 9–12 на нижней линии H1, уже — под заголовком. H1 —
  `clamp(2.2rem, 2.9vw, 2.75rem)`, строки не переносятся. Запас под параллакс —
  124 % высоты секции и сдвиг 8 % (было 140 % и 12 %): кадр меньше увеличен,
  края упаковки и логотипа не срезаются. Затемнение — три слоя: сверху под
  шапку (.55 → 0 на 22 %), снизу под текст (.9 → .8 на 20 % → .55 на 27 % → 0
  на 36 %) и ровный слой .12. На невысоких экранах, где кнопки ещё стоят под
  заголовком (уже 1280px и ниже 950px), H1, зазоры и нижний отступ сжаты в две
  ступени, а плотная часть нижнего слоя поднята (.84 на 24 %, .66 на 29 %):
  иначе три ряда текста поднимались в зону логотипа и выходили из-под
  затемнения. Проверено дополнительно на 1194×834, 1180×820, 1024×600, 800×600
  и 1280×600.
* **Узкая** — всё остальное: портрет любой ширины и низкий горизонтальный экран.
  Горизонтальный ролик во весь экран телефона обрезался бы до пятой части
  ширины вместе с логотипом, поэтому видео стоит кадром сверху, текст — под ним
  на `--void` и заходит на кадр на 2.5rem. Кадр 4:5 (портрет уже 768px,

### Альтернативная главная 2 (`/alt2`)

Черновик для показа, собран 23.09.2026. Живёт в `alt2/index.html`,
`src/alt2/**` и двух файлах данных (`src/data/caviar-lines.js`,
`src/data/origin.js`); основная главная, `/alt`, каталог, карточка, корзина
и сборка Битрикса не тронуты. Стенд не заливался.

**Зачем.** Владелица компании посмотрела сайт: он функциональный, но не
премиальный и не показывает главного — качества и происхождения продукта.
Образец подачи — rossinicaviar.com: характеристики видов икры и страница
о происхождении. Магазин при этом должен остаться магазином и с первого
экрана показывать, что здесь продаётся весь стол, а не только икра и рыба.

Покупатель не отличает икру разных производителей. Большая часть чёрной
икры на рынке выращена в других странах и часто получена прижизненным
способом, а №1 Caviar — забойная, с Каспия. Сказать это прямым сравнением
нельзя — закон о рекламе запрещает некорректное сравнение, и выпад выглядит
дёшево. Поэтому страница даёт способ отличить самому: паспорт линейки,
способ получения икры в разрезе зерна и код СИТЕС на банке. Первые два
блока — интерактивные: так попросила владелица.

#### Как устроено

* **Сборка.** `src/alt2/main.js` — копия `src/main.js` с тем же порядком
  вызовов; класс `is-alt2` на `<body>`, стилей старого первого экрана,
  `#types` и `#why` нет. `src/alt2/sections.js` — свой реестр и свой
  `initSections` (`initStage`, `initCharacter`, `initOrigin`, `initProof`,
  `initShop`, `initOffline`): общий `initSections` поднял бы `initHero`,
  который ищет разметку старого первого экрана. Первый экран сохраняет
  `id="hero"` — на нём держатся шапка, кольцо и виджет эксперта.
* **`src/alt2/alt2.css`** — акцентный шрифт Cormorant Garamond (курсив 400/500,
  только крупные числа и номера), зерно `feTurbulence` на `#hero`, `#origin`,
  `#proof` (`::after`, `opacity .05`, `overlay`, под слоем секции) и стили
  капсулы версий.
* **Первый экран** (`src/alt2/sections/stage.js`). Шесть разделов списком,
  кадр активного — справа от колонки 6 до края окна (узкая раскладка —
  сверху). Кадры лежат стопкой, смена — растворение 700 мс и масштаб
  1.06 → 1 за 6 с. Пока человек не тронул список, разделы сменяются сами
  каждые 5 с (полоса под строкой — таймер; на узкой — шесть сегментов под
  кадром); первое наведение или фокус выключают автосмену до перезагрузки.
  Кадр следует за курсором (±12 / ±8 px, `quickTo` 0,8 с). Строка «Рыба»
  показывает ролик бренда, отрезок 4,4–13,8 с по кругу; при Data Saver, 2G
  и `prefers-reduced-motion` — постер. Счётчики позиций считаются из
  `categoryItems` и позиций прототипа, склонение — `plural()`.
* **«Характер икры»** (`src/alt2/sections/character.js`). Вкладки видов
  (`tablist`, стрелки, Home/End), строка линеек, большой круг с зерном вида
  и лупой (линза 180px, ×2,4; мышью и касанием), малый круг с банкой
  линейки, паспорт из одинаковых признаков, линейка зерна (все линейки
  кругами на одной оси, диаметр — зерно в масштабе) и шкала возраста.
  Выбор — в адресе (`?line=<слаг>`, `replaceState`) и в событии
  `gg:line-change`. «Выбрать фасовку» ведёт в раздел чёрной икры
  с `?grade=<сорт>`: фильтр раздела читает его сам.
* **«Происхождение»** (`src/alt2/sections/origin.js`). Две истории вкладками.
  На широкой раскладке шаги слева, кадр справа липкий; активен шаг, который
  пересёк середину экрана. Кадр шага — один узел на обе раскладки: при смене
  раскладки он переезжает между шагом и липким кадром. Виджеты: `years`
  (0 → 30 один раз), `shell` (зерно в разрезе, забойная / прижизненная),
  `radius` (окружность «800 км» один раз), `cites` (крышка банки с кодом;
  первая группа — вид рыбы линейки из `#character`).

### Горизонтальная лента витрины (`src/js/rail.js`)

Механизм остался один — у `#shop`. `#categories` на него больше не опирается:
там решётка без прокрутки.

Прокрутка **нативная** — `overflow-x` плюс `scroll-snap`; `touch-action`
не трогаем, драг мышью по самим карточкам не эмулируем (он ломает выделение
и клик по карточке).

**Переделано по правке заказчика.** Единственным органом управления был
пейджер, стоявший в строке с переключателем «Себе / В подарок» — то есть НАД
лентой и сбоку от неё. Заказчик сказал прямо: эти стрелки не находятся, а рука
тянется к низу ленты, где у слайдеров обычно ползунок. Способов листать стало
три, и все три там, где их ищут:

1. **Ползунок под лентой.** Полоса позиции перестала быть только индикатором:
   за золотой отрезок тянут, по дорожке щёлкают — лента едет в это место.
   Главный способ. Дорожка 3 px (под курсором и во время протяжки — 5), зона
   захвата растянута псевдоэлементом на 11 px вверх и вниз, курсор меняется
   на `grab` / `grabbing`. `scrollLeft` двигаем напрямую, без
   `behavior: 'smooth'`, иначе отрезок отстаёт от руки; на время протяжки
   снимаем `scroll-snap`, иначе браузер подтягивает каждое присваивание
   к ближайшей карточке и ползунок идёт рывками.
2. **Пейджер.** Та же капсула на две кнопки с волосяной перегородкой, но
   переехала вниз и встала с ползунком в одну строку: стрелки и ползунок
   читаются одним органом управления. Скрыт на тач-устройствах.
3. **Стрелки поверх краёв ленты.** Всплывают по наведению на ленту, только
   там, где есть курсор. `aria-hidden` и `tabindex="-1"`: в дерево доступности
   они не идут, иначе скринридер объявлял бы четыре кнопки листания вместо
   двух. Кнопка на своём краю не гаснет наполовину, а исчезает совсем —
   полупрозрачная стрелка поверх фотографии читается как брак печати.

Плюс пассивный знак, который был и раньше: **обрезанный край** — маска гасит
содержимое с той стороны, куда ещё есть куда ехать, стороны считаются
отдельно. Маска висит на самом скроллере, а не на обёртке: обёртка держит ещё
и строку ползунка, и её концы гасились бы вместе с карточками.

Вся индикация снимается разом, если лента влезла целиком (`is-scrollable`
ставит JS): мёртвые кнопки с ползунком во всю дорожку были бы обманом.

Витрина подменяет ленту целиком при смене набора, поэтому `initRail()` отдаёт
`destroy()` — без отписки на кнопках копились бы обработчики от всех прошлых
лент. `prev` / `next` принимают массив: на каждое направление теперь по две
кнопки — в пейджере и поверх края.
- **#why** — см. отдельный раздел «Блок обязательств» ниже: сетка 3×2
  заменена разворотом «список слева, панель справа».
- **#offline** — в списке только подтверждённые города, их пять: Санкт-Петербург
  заказчик подтвердил, и он вернулся вторым, сразу после Москвы. Порядок
  не алфавитный — сначала главный российский город, потом остальные
  российские, потом зарубежные; и этот же порядок обязан повторять массив
  кадров в `src/data/media.js`, на совпадении держится миниатюра у курсора.
  Раскладка списка одноколоночная: двух колонок требовали шесть городов,
  при пяти список по-прежнему короче текста слева. Флагманский бутик в ЖК
  «Золотой» на Софийской набережной назван в тексте отдельной фразой,
  а не строкой списка: в списке все города равны, а это главный адрес
  компании.
- **#proof** — композиция не менялась, заказчик её принял. Цифры заменены на
  данные заказчика, кегли и отступы срезаны (687 → 587). У значения есть
  необязательные `prefix` и `suffix` («с » у года, «+» у числа клиентов):
  они не участвуют в отсчёте, иначе мигали бы вместе с числом. Год основания
  не отсчитывается вовсе (`count: false`) — бегущие «0 → 1982» читаются как
  сломанный счётчик. Отбивка приставки задана полем, а не пробелом: пробел
  между flex-элементами схлопывается, и «с 1982» превращалось в «с1982».
- **#journal** — карточка целиком одна ссылка: один табстоп вместо трёх.
  Заголовок обрезается по трём строкам, лид — по двум.

### Секция «Сезон и новинки» (`#season`)

**Живёт только на `/alt`.** С основной главной снята 16.09.2026 по решению
Дениса. Вернуть — одна строка `{ id: 'season', dark: false, full: false, tight: true }`
после `shop` в `src/data/sections.js` и импорт `styles/sections/season.css`

Заказчик просил блок с сезонными хитами и новинками, компактный и оформленный
иначе, чем витрина `#shop`.

**Почему не вторая лента карточек.** Два одинаковых ряда карточек на одной
странице читаются как сбой сборки, а не как два разных предложения. Поэтому
блок построен на другой типографической механике: строчный список слева
и одно окно предпросмотра справа.

```
СЕЗОН И НОВИНКИ
Сейчас в сезоне
Позиции, которые мы отбираем на ближайшие недели.

[Сезон]  Икра белуги Роял            Цена по запросу   ┌──────────┐
         Банка металл, 125 г                           │  кадр    │
──────────────────────────────────────────────         │  4:5     │
[Новинка] Икра осетра персидского    Цена по запросу   └──────────┘
          Банка стекло, 113 г                          Икра белуги Роял
… ещё четыре строки
Все новинки →
```

* строка целиком — ссылка на карточку товара. Разделены волосяными линиями,
  тем же приёмом, что города в `#offline` и пункты `#why`;
* у активной строки поверх волосяной прочерчивается золотая линия слева
  направо, метка и название темнеют;
* **окно — приглашение, а не украшение.** Пока курсор не касался блока, кадр
  сам перелистывается раз в 4.5 с: это и есть подсказка, что строки живые.
  Первое наведение или фокус останавливают листание навсегда — вернувшееся
  листание перебивало бы выбор человека;
* окно помечено `aria-hidden`: оно дублирует написанное в строке, и
  скринридеру незачем слышать название дважды;
* ниже 1024 px окна нет вовсе, строки получают квадратную миниатюру 56×56
  слева. Автолистания там тоже нет — листать нечего;
* `prefers-reduced-motion`: ни автолистания, ни кроссфейда; смена кадра
  мгновенная, золотая линия сразу в конечном виде.

**Место в порядке.** Сразу за `#shop`, с флагом `tight` и без своего `ring`:
это продолжение главы витрины, а не новая глава. «С чего обычно начинают» —
постоянное, «Сейчас в сезоне» — временное.

⚠ **Состав блока ждёт подтверждения заказчика.** Признака сезонности
и новизны в выгрузке 1С нет вовсе. Подробности — в шапке `src/data/season.js`
и в таблице «ждут подтверждения» выше. Названия, фасовки и цены при этом
не выдуманы: строки собираются по слагу из настоящих позиций, придумать здесь
новое название физически нельзя. Серых заглушек в блоке нет — все шесть
кадров уже сняты.

### Блок обязательств (`#why`)

**Заголовок.** Было «ПОЧЕМУ МЫ» / «Почему заказывают у нас». Заказчик прав:
премиальный бренд не объясняет, почему у него покупают, — он заявляет, за что
отвечает. «Почему» переводит бренд в оборонительную позицию. Стало «НАШ
СТАНДАРТ» / «Что мы берём на себя»: тот же смысл, сказанный с позиции
обязательства. Шесть пунктов не менялись — они и есть перечень обязательств.
Остановка кольца переименована вслед за заголовком: «Почему мы» → «Стандарт».
Запасные варианты заголовка лежат комментарием в `src/data/why.js`.

**Идентификатор секции остался `#why`.** Он завязан на сборщик, файл стилей,
реестр секций и якоря подвала; переименование ради красоты — правка в трёх
местах, где легко ошибиться, и ноль пользы на экране. Прецедент уже был:
при замене `#delivery` → `#why` менялись содержимое и подписи, а не id.

**Форма.** Сетка 3×2 из шести плиток «знак — заголовок — три строки» —
самая узнаваемая заготовка в интернете, и нажимать она не зовёт. Вместо неё
разворот:

```
  ⬦ Ресторанный уровень
────────────────────────────      ┌─────────────────┐
  ⬦ Максимальная свежесть         │  кадр 4:3       │
────────────────────────────      └─────────────────┘
  … ещё три строки
```

**Чего здесь нельзя потерять при переписывании: все шесть заголовков видны
ВСЕГДА.** Интерактив раскрывает только подробности и кадр. Блок, в котором
«Собственное производство» надо сначала найти наведением, перестал заявлять
и начал загадывать — а это блок обязательств.

* активный пункт: заголовок темнее, знак золотой, слева прочерчена
  вертикальная золотая линия;
* переключение по наведению и по нажатию; смена панели — кроссфейд со сдвигом
  12 px, 280/320 мс, `power3.out`. Знак активного пункта прорисовывается
  по контуру — та же механика `stroke-dashoffset`, что была у сетки;
* автолистание раз в 5 с с тонкой золотой полосой прогресса под активным
  заголовком: полоса и есть подсказка, что здесь можно вмешаться. Первое
  наведение, нажатие или фокус останавливают его навсегда;
* клавиатура: `role="tablist"` / `tab` / `tabpanel`, roving tabindex, стрелки
  ↑↓ и ←→, `Home` / `End`;
* ниже 900 px двух колонок нет: список превращается в аккордеон, заголовки
  по-прежнему видны все, первый раскрыт, высота анимируется. Роли там другие —
  кнопка с `aria-expanded` и `region`: обещать контракт вкладок панели,
  которая раскрывается под своим же заголовком, было бы неправдой;
* `prefers-reduced-motion`: ни автолистания, ни кроссфейда, ни прорисовки
  контура, ни полосы прогресса.

**Разметка одна на оба режима**: строки и панели лежат вперемешку (строка →
её панель → строка → её панель). На десктопе сетка уводит панели в правую
колонку и складывает их друг на друга, на мобильном тот же DOM читается
сверху вниз. Переносить узлы при смене ширины не нужно — а перенос ломает
фокус и рвёт анимацию на полуслове.

**Контраст замерен в обеих темах** (светлая / тёмная), порог 4.5:1:

| Что | Светлая | Тёмная |
|---|---|---|
| Заголовок активного пункта | 14.8:1 | 15.4:1 |
| Заголовок неактивного пункта | 5.2:1 | 7.1:1 |
| Текст панели | 14.8:1 | 15.4:1 |
| Метка «Сезон» / «Новинка» в `#season` | 5.0:1 | 5.5:1 |

### Ритм хвоста

Три светлые секции подряд (`#offline`, `#why`, `#journal`) легко читаются
одним полотном. Разводятся они не фоном, а типографикой:

* Тестовые позиции чёрной икры (`pin`) стоят первыми и здесь: так работает

### Поиска по разделу здесь больше нет

Заказчик прав: поиск по сайту есть в шапке, и второе поле на том же экране
читается как дубль — человек выбирает между двумя одинаковыми на вид
инструментами вместо того, чтобы искать.

Убрано целиком, а не спрятано: модуль `src/js/catalog/search.js` удалён,
из состояния убран `query` и параметр `?q=` (`state.js`), из отбора —
`matchesQuery` (`model.js`), из применённых фильтров — чип «запрос»
(`filters.js`), из данных — блок `search` (`category-copy.js`).
Заодно убрана иконка поиска из липкой полосы: поля, к которому она
возвращала, больше нет, а кнопка, ведущая в никуда, — сломанный
переключатель, а не компромисс.

**Что осталось и почему.** `normalize` и `highlight` в `model.js` никуда
не делись: ими пользуется поиск по значениям ВНУТРИ поповера длинной пилюли
(порог — восемь строк). Это другой инструмент — он ищет не товары, а значения
одной фасеты, и на экране с ним ничего не конкурирует. Поиск в шапке
(`src/js/nav/search.js`) тоже не тронут.

Текст пустой выдачи поправлен вслед за правкой: было «Попробуйте изменить
запрос или сбросить фильтры», стало «Попробуйте снять фильтр или сбросить
всё» — запроса больше нет.

Липкая полоса появляется, когда панель пилюль уходит вверх: на десктопе под
шапкой, на мобильном — снизу, под большой палец.

### Как развязаны конфликты

**Два поиска — конфликта больше нет: поиск остался один.** Раньше их было
два — иконка в шапке по всему сайту и поле внутри раздела, — и разделялись
они тремя строками текста. Заказчик прав, что это дубль: правильный ответ
на «где искать» должен быть один. Поле раздела убрано целиком, см. раздел
выше; поиск по сайту живёт в шапке и доступен на любой прокрутке, потому что
шапка липкая.

**Три уровня навигации — уровня два.** Подкатегория в мега-меню это не раздел,
а сохранённый фильтр: `?sub=holodnoe-kopchenie` разворачивается в значение
фасеты, и адрес тут же переписывается в канонический
`?processing=Холодного+копчения`. Хлебные крошки всегда трёхчленные, H1 всегда
«Рыба», а где человек находится, показывают активный таб и снимаемый чип в
строке применённых фильтров. Из подкатегории всегда есть выход одним нажатием.

Правило, которое из этого следует: **подкатегория ложится ровно на одну ось**.
После выгрузки из 1С подкатегории рыбы — это ровно ось «Обработка», четыре
значения: придуманных видов («Лосось и форель», «Осетрина», «Белая рыба»)
в панели больше нет, вида как отдельной оси в учёте не заведено. У чёрной
икры восемь подкатегорий разведены по трём осям — четыре по виду, одна
по линейке (паюсная) и три по фасовке, — и каждая по-прежнему лежит ровно
на одной. После перестановки осей (см. ниже) вид лёг на капсулы, линейка
на пилюлю «Сорт», фасовка на табы — раскладка сменилась, правило нет.
Правила — `subFilters` в `src/data/facets.js`.

**Универсальность фасет — схема в данных.** У фасеты три роли, и больше вёрстка
не знает: `chips` (капсулы, множественный выбор), `tabs` (табы, одиночный),
`pill` (пилюля с поповером). Категория объявляет, что где стоит:

| Раздел | chips | tabs | пилюли |
|---|---|---|---|
| Рыба | Вид рыбы | Обработка | Выгода · Вкус · Упаковка · Страна · Бренд · Вес · Цена |
| Чёрная икра | **Вид** | — | **Сорт** · Фасовка · Упаковка |
| остальные | — | — | Выгода · Бренд · Страна · Цена |

**Оси чёрной икры переставлены по правке заказчика: «Вид» — в строку, «Сорт» —
в фильтры.** Раньше капсулами стояли девять линеек, и он прав дважды:

* девять линеек в строку не влезают и переносятся на вторую — главная ось
  раздела выглядела свалкой, а не выбором. Четыре вида встают в одну ровную
  строку;
* на главной блок «Икра по видам» показывает ровно эти четыре вида. Человек,
  пришедший оттуда по кругу «Белуга», попадает на страницу, где «Белуга»
  стоит на том же месте и в том же виде. Раньше он попадал на страницу,
  где главная ось — девять линеек, и своего выбора не находил;
* у раздела «Рыба» главная ось — «Вид рыбы». После правки обе рабочие
  категории устроены одинаково: вид → способ или фасовка → остальное.

Сорт при этом не потерялся: он стал полноценной пилюлей, и поскольку значений
девять, поиск по списку внутри поповера включается сам (порог — восемь строк).
Порядок девяти линеек задан полем `order`, иначе список уехал бы в алфавит
и «Белуга и стерлядь SELECTED» встала бы между «Даймонд» и «Премиум».

**У икры пилюли «Вес» нет намеренно**: фасовка стоит пилюлей и закрывает ту же
ось. Табами она была до появления строки «Наличие» — строку над панелью
фильтров заняло наличие, см. раздел «Корзина и оформление». Две оси веса в одной строке — типовая ошибка каталогов, из-за неё счётчики
начинают противоречить друг другу.

Списки значений **не пишутся руками**: `collectOptions()` собирает их из самих
товаров, поэтому список опций и данные разъехаться не могут. Поле `order`
задаёт порядок там, где алфавит бессмыслен (обработка, фасовка, виды рыбы —
иначе первым в строке встал бы «Клыкач»).

**Плотность — среднее между прототипом и главной.** Прототип фильтров свёрстан
на 14px: это обычный магазин. Взято управление на 0.78–0.82rem с трекингом —
тот же регистр, что у переключателя витрины; карточка типографикой ровно как в
`#shop`; сетка 4 / 3 / 2 / **2** колонки. На мобильном именно две: колонка
гигантских карточек делает страницу бесконечной, а премиальность даёт не размер
карточки, а воздух вокруг неё. Теней нет нигде, включая поповер и боттом-шит.

### Карточка товара — общий компонент

`src/js/components/product-card.js` и `styles/components/product-card.css`.
Ими пользуются и витрина главной, и сетка каталога: копия разошлась бы с

### Что перенесено из прототипа фильтров дословно

- **Фасетные счётчики с исключением собственной фасеты.** Выбор внутри «Бренда»
  не меняет счётчики самого «Бренда», но меняет все остальные. Это главное, что
  теряется при переписывании: без исключения человек, выбрав один бренд, видит
  у всех прочих нули и решает, что в разделе больше ничего нет.
- **Опция с нулём выключается, но не прячется** — исчезающие строки читаются
  как сбой.
- Семь сортировок; **сортировка никогда не считается активным фильтром** и не
  попадает в счётчик у кнопки «Фильтры».
- Свой поиск внутри длинных списков опций (порог — восемь строк). После
  перестановки осей у чёрной икры он включается у пилюли «Сорт»: линеек девять.
- **Мобильный боттом-шит с черновым состоянием.** Фильтры внутри не применяются
  на лету: кнопка внизу показывает, сколько получится («Показать 7 товаров»), и
  только нажатие переносит черновик на страницу. Исключение — сортировка,
  она применяется сразу.
- Пустая выдача: подсказка с именем первого снятого фильтра, сброс и блок
  «Часто выбирают».

### Что сделано иначе, чем в прототипе

| Было | Стало | Почему |
|---|---|---|
| состояние в `location.hash` | query-строка и `replaceState` | хэш на сайте занят якорями и переходами Lenis, а мега-меню ведёт на `?sub=`; «назад» из каталога должно возвращать на предыдущую страницу, а не отматывать двадцать нажатий по фильтрам |
| своя шапка 56px с логотипом | настоящая шапка сайта | конфликт 4 из списка |
| SVG-иллюстрации в карточках | кадры через `media.js` | заглушка с именем файла и пропорцией — общий механизм прототипа |
| `role="tab"` у строки обработки | кнопка с `aria-pressed` | за табом должна стоять панель; здесь её нет, и обещать скринридеру контракт вкладок нечестно |
| поиск по разделу | убран целиком | по правке заказчика: поиск по сайту стоит в шапке, и второе поле на том же экране заставляет выбирать между двумя одинаковыми инструментами. Вместе с полем ушли подсказки раздела, параметр `?q=` и иконка поиска в липкой полосе |
| «В подарочной упаковке» в ряду обработки | ушло в фасету «Упаковка» | это свойство упаковки, а не обработки: ось-таб должна быть одной осью |

| `facets.js` | состав осей и пилюль по разделам |
| `catalog.js` | ничего: дерево собрано по выгрузке 1С, у каждой строки код `code1c`. Предварительны в нём только подборка «Хиты продаж» (статистики продаж нет) |

### Чего на странице ещё нет

- **Корневая `/catalog`** — витрина всех категорий. Сейчас там заглушка,
  её нужно спроектировать отдельно.
- **Синонимы в поиске по сайту.** Запрос «сёмга» ничего не находит:
  в данных вид назван «Лосось». Частично это закрыто списком синонимов
  разделов (`src/data/search.js`), но настоящий каталог потребует
  полноценного словаря.
- **Отдельные адреса под частые сочетания фасет.** Для SEO популярным парам
  «категория + фасета» со временем понадобятся собственные страницы со своим H1
  и текстом; в прототипе они намеренно остаются фильтром.

## Карточка товара

`/product/<слаг>` — **один шаблон на все позиции каталога**. Адресов 90:
52 позиции чёрной икры из выгрузки 1С и три тестовые, 12 позиций красной
икры по снимку стенда и 23 демонстрационные позиции рыбы.
Список не ведётся руками ни в карте сайта, ни в генераторе — он собирается
из `src/data/catalog-products.js`, как каталожная колонка подвала собирается
из каталога.

Точка входа своя (`src/product.js`), отдельная от `src/page.js`: там общий
каркас четырёх десятков заглушек — одна колонка текста, и тащить в него
галерею с лентами незачем. То же решение, что у страницы категории.

### Вкладок нет ни одной, и это решение

**Вкладки «Отзывы» нет.** Отзывов по товарам не существует ни в каком виде,
а придумывать их нельзя — это то же самое, что придумывать цифры. Вкладка
«Отзывы (0)» на банке премиальной икры читается как поломка. Социальное
доказательство на сайте уже собрано в одном месте: тёмный блок `#proof`
на главной и страница `/reviews`. Внизу карточки стоит одна строка со ссылкой
туда.

**Вкладок нет и вообще.** Содержимого на карточке икры немного, и вкладки
прятали бы половину того, что и так помещается на экран. Вместо них одна
колонка блоков через волосяную линию — грамматика всего сайта (`#offline`,
`#why`, `#trust`). Ни табов, ни аккордеонов, ни рамок с заливкой.

### Выбор фасовки — не декорация

Фасовки одной линейки — это **разные позиции с разными слагами**, поэтому
переключение уводит на адрес другой позиции, а не подсвечивает капсулу
на месте. Капсулы — настоящие ссылки `<a href>`.

Список собирается из данных, а не пишется руками:

* фасовки, которой у линейки нет, в ряду не будет;
* ряд «Упаковка» показывает только те упаковки, которые есть **у выбранной
  фасовки**: у 50 г бывает и металл, и стекло, у 250 г только металл.
  Показывать недоступную упаковку значит врать о наличии;
* ряд с единственным значением не рисуется вовсе — переключатель без выбора
  это брак. У позиций рыбы, где линейки нет, обоих рядов поэтому нет;
* при смене фасовки текущая упаковка сохраняется, если она есть у новой
  фасовки: человек выбирал вес, а не переезд со стекла на металл.

### Характеристики — только то, что есть в учёте

`<dl>` в две колонки. Выводятся ключи, которые реально лежат в `attrs`
позиции: у икры это вид, линейка, фасовка, упаковка и вес; у рыбы к ним
добавляются обработка, вкус, страна и бренд. **Ни «размера зерна», ни
«вкуса» у икры, ни срока годности** — этих данных в выгрузке нет, и
придумывать их нельзя. Порядок и подписи — в `src/data/product-copy.js`.

По той же причине тексты «Как хранить» и «Документы» написаны про продукт
вообще, а не про конкретную банку, и в самих блоках это сказано прямо:
сроков годности, дат фасовки и номеров партий в выгрузке нет.

### Галерея

Главный кадр 1:1 и лента миниатюр под ним; переключение мгновенное, без
слайдера — это выбор ракурса, а не показ. Клавиатура: стрелки, `Home` / `End`.

**Лента рисуется только если кадров больше одного.** Одна миниатюра под
кадром — переключатель, которому нечего переключать. У чёрной икры кадров
три: снятый кадр вида плюс два ракурса, которые ждут съёмки (`-detail`
и `-serving`, восемь файлов на четыре вида — см. список ожидаемых медиа).
Пока файлов нет, на их месте штатные заглушки. У рыбы ракурсов не снято,
и ленты под кадром нет вовсе.

### Ленты внизу

Общий компонент карточки (`createProductCard`) и общая механика прокрутки
(`src/js/rail.js`) — те же, что у витрины главной. Лента из одной карточки
не лента: блок в этом случае не заводится совсем.

* **Другие фасовки этой линейки** — остальные позиции той же линейки;
* **Другие виды икры** — по одной представительной позиции на каждый вид,
  кроме вида текущей позиции. Представитель берётся с той же фасовкой, если
  она у вида есть: ряд карточек с разным весом читался бы как случайная
  подборка. Заголовок берётся по разделу — у рыбы это «Другие виды рыбы».

### Кнопки

Под ценой — строка статуса с ромбом: «В наличии · доставка день в день по
Москве» или «Под заказ · привезём примерно за 7 дней». Рядом с «В корзину» —
степпер количества той же высоты, что кнопка; товар кладётся в настоящую
корзину (раздел «Корзина и оформление»), тост ведёт на `/cart`.
«Спросить эксперта» шлёт событие `expert:open` и поднимает угловой виджет —
заводить на карточке вторую такую же форму значило бы удвоить точку приёма
заявок. У позиции без цены эта кнопка называется «Узнать цену».

**«Сообщить о поступлении»** (22.09.2026) — отдельной строкой под рядом
кнопок, только у позиции, которая идёт заявкой менеджеру и которой нет
на складе (`kindOf(product) === 'request' && !product.inStock`): у позиции
в наличии ждать нечего, «под заказ» можно купить сейчас. В сетке, лентах
и поиске кнопки нет. Подписка есть только у вошедшего — СМС уходит на номер
кабинета; гостю открывается окно входа. Подробности — «Личный кабинет, вход
и избранное → Лист ожидания».

**Позиция в коробках с разным весом** (22.09.2026, выбор в карточке
с 23.09.2026, «Корзина и оформление → Коробки»): под названием цена
отмеченных коробок и мелко «за коробку 202 г» (при нескольких — «5 676 ₽
за 2 коробки · 202 и 238 г»); под ценой строка «1 290 ₽ за 100 г · каждая
коробка взвешена, цена по её весу»; после метки вида один селектор
`.boxsel` — строка «Коробка 202 г» с галочкой вниз, которая выпадает
списком весов и цен (`src/js/product/box-picker.js`, список —
`src/js/components/box-list.js`). **Весь список коробок на страницу
не вываливается** — этого Денис и просил избежать: закрытый селектор
занимает одну строку, кому вес неважен, тот его не открывает.

Селектор и степпер — одно состояние: сколько коробок, решает степпер, какие
именно — селектор. При одной коробке список — радиокнопки, и выбор сразу
закрывает панель; при двух — флажки, счётчик «Отмечено 2 из 2», остальные
выключены, а сняли одну — цена и степпер ждут, пока отметят вторую (закрыли
раньше — недостающую подберёт сама). «+» отмечает ближайшую к номиналу
из свободных, «−» снимает последнюю; максимум — число свободных, упёрлись —
«На складе 11 коробок». Панель закрывают Esc, клик мимо и повторное нажатие;
фокус возвращается на селектор. «В корзину» кладёт ровно отмеченные.
В характеристиках «Вес коробки — около 200 г» (стандарт; точный вес —
в селекторе). Под заказ (коробок нет): «≈ 1 980 ₽ за коробку», строка
«990 ₽ за 100 г. Вес коробки станет известен при фасовке, точную сумму
пришлём СМС до оплаты.», селектора нет. Ряда «Фасовка» у коробок нет.
Список коробок карточка берёт через `cart/boxes.js` асинхронно; до его
прихода цена — коробки по умолчанию из данных, та же.

## Корзина и оформление

Четыре рабочие страницы — `/cart`, `/checkout`, `/order-success`, `/delivery` — плюс
модель наличия, которая меняет каталог и карточку товара. Первая задача —
`PROMPT-korzina-i-oformlenie.md`, вторая (16.09.2026, три вида позиции и заявка
менеджеру) — `PROMPT-zakaz-i-zayavka.md`; ниже — что сделано и где решения
разошлись с заданиями.

### Три вида позиции (16.09.2026)

Вид считает **одна** функция — `kindOf` в `src/data/fulfillment.js` (на Битриксе
`gg_item_kind` в `include/catalog.php`), больше нигде он не угадывается:

| Вид | Условие | Что можно |
|---|---|---|
| `stock` · В наличии | есть на складе и есть цена | заказать и оплатить, доставка день в день |
| `preorder` · Под заказ · 7 дней | нет на складе, есть цена, раздел с `fulfillment: 'preorder'` в `src/data/catalog.js` — «Рыба» и «Красная икра» со всеми подразделами | заказать и оплатить, привезём через `PREORDER_DAYS` |
| `request` · Через менеджера | всё остальное: не на складе вне рыбы и красной икры, **включая чёрную икру**; позиция без цены в любом разделе; на Битриксе — позиция без `CAN_BUY` | оплатить нельзя, уходит менеджеру заявкой |

**В заказе больше не бывает позиций «по запросу».** Заказ всегда с точной суммой;
ветка «цена по запросу» (`allOnRequest`, «Отправить заказ на подтверждение»,
шаг «Пришлём ссылку на оплату») удалена целиком. Позиция витрины главной
раздела не имеет: в наличии и с ценой — `stock`, иначе `request`. Дата
готовности считается только по позициям заказа.

**Метка вида** — один компонент на весь сайт, `.stock-tag`
(`src/js/components/stock-tag.js`, `src/styles/components/stock-tag.css`):
строка со знаком 14 px (`check`, новый `clock`, `dialog`), без рамки. В сетке —
только у «под заказ» и «через менеджера», на карточке товара — у всех трёх, рядом
одно предложение («Закажем и привезём к 23 сентября»). Приглушённого кадра
и приписки «· под заказ» к фасовке больше нет. Кнопка в углу кадра — «В корзину»
или «В заявку», главная кнопка карточки у заявки — «Добавить в заявку».
Все кнопки кладут позицию одной функцией `addWithToast` (`src/js/cart/add.js`):
тост зависит от вида.

**Корзина** — одна на все виды, позиции разложены группами «В наличии»,
«Под заказ», «Заявка менеджеру». Заголовки групп показываются всегда: строка
под заголовком — обещание по срокам, прежняя строка готовности над сводкой ушла.
Сводка заказа считает только `stock` и `preorder`; блок «Заявка менеджеру —
2 позиции, в итог не входят»; подсказка про раздельную доставку — только когда
в заказе оба вида; кнопка «Оформить заказ» / «…заказ и заявку» / «…заявку»;
промокод — только при заказе. Полоса итога ниже 480 px пишет «Оформить»,
полный текст остаётся для скринридера. Демонстрационное наполнение —
`/cart?demo=mixed|order|request|boxes` (`src/js/cart/demo.js`, только прототип).

**Оформление** — три режима одной страницы, нумерация шагов сквозная. Когда
в заказе есть и наличие, и под заказ, шаг «Когда» начинается с выбора «Одной
доставкой» / «Двумя доставками» (при самовывозе — «визитом»): у двух доставок
свои ленты дней (наличие — от сегодня до дня перед готовностью, под заказ —
от дня готовности на 14 дней), интервалы и проверка. Шаг «Заявка менеджеру» —
состав без сумм, способ связи, вопрос. `submitCheckout` создаёт заказ и/или
заявку (`gg-requests`, номера с 501) и уводит на `/order-success?n=…&r=…`.

**Заявка на Битриксе** хранится не в корзине: cookie `gg_request` до отправки,
элемент инфоблока `gg_requests` и письмо `GG_MANAGER_REQUEST` после. Вид
пересчитывается при каждой отрисовке, позиции переезжают между корзиной
и заявкой сами. Подробности — `bitrix/templates/grandgurme/README.md`.

### Коробки с разным весом (22.09.2026, выбор в карточке с 23.09.2026)

> Решение менялось дважды за день. 22.09: приблизительные вес и цена везде,
> подбор коробок на оформлении. 23.09 (первая правка): выбор переехал
> в карточку, «≈» убрано из каталога. 23.09 (вторая правка, действующая):
> выбор в карточке спрятан в один выпадающий селектор, **в каталоге —
> стандартный вес и цена по номиналу**, цены **округляются до рубля**.

Большая часть рыбы продаётся коробками: коробка «около 200 г» весит от 174
до 238 г, каждая уже взвешена и запечатана, 1С знает, какие лежат на складе.
На действующем сайте человек выбирает из 11 кнопок с весами. **Решение
Дениса 23.09.2026** (взамен решения 22.09 «приблизительно до оформления,
выбор на оформлении» — там выбор терялся в форме, и строку в корзине могли
не прочитать): коробка выбирается **в карточке**, по умолчанию отмечена
ближайшая к номиналу, а сам список спрятан в выпадающий селектор — весь
набор коробок на страницу не вываливается. Корзина показывает выбранные
веса, «Выбрать другие» открывает окно. На оформлении выбора нет. Кому вес
неважен, тот разницы с обычным товаром не замечает.

**В каталоге — стандарт.** Сетка, поиск и избранное пишут номинальный вес
и цену по номиналу: «Коробка 200 г», «2 580 ₽», без «≈». Конкретный вес
и его цена — дело карточки, где коробку и выбирают. «≈» осталось только
у коробки под заказ, которой на складе нет: в карточке «≈ 1 980 ₽
за коробку», в корзине и заказе «Коробка ≈ 200 г · взвесим при фасовке».
**Цены без копеек:** цена коробки округляется до рубля (12 900 ₽ ×
0,174 кг = 2 244,6 → 2 245 ₽), суммы складываются из округлённых цен.
На стенд переносит Cowork по записке `PERENOS-korobki.md`; данных для этого
на стенде пока нет.

**Модель** (`src/data/boxes.js`). Позиция в коробках отличается тремя
полями: `sale: 'box'`, `pricePerKg`, `nominalG` и списком свободных коробок
`packs: [{ id, weightG }]`. Обёртка `withBoxFields` выводит **стандартные**
`weightG` (номинал — пилюля «Вес», сортировки), `weightLabel` («Коробка
200 г») и `price` (цена коробки номинального веса — пилюля «Цена»,
сортировки, `kindOf`), а также `inStock` и `defaultPack` (коробка
по умолчанию — карточке для первой отрисовки цены). Чистые функции:
`packPrice` (цена коробки, округлённая до рубля), `pricePer100`,
`defaultPack`, `pickPacks` (n ближайших к номиналу, при равенстве более
лёгкая, по возрастанию веса, `exclude` — id, которые брать нельзя),
`nearerTo` (сравнение «кто ближе к номиналу» — им упорядочивается
добавление коробок к уже выбранным, чтобы при уменьшении количества
уходили самые далёкие), `weightsText` («204 и 206 г»), `packsWord`,
`boxLabel` / `boxLabelApprox`. Граница
«свободные коробки» — `src/js/cart/boxes.js`: `getFreePacks(slug)`
асинхронно (ряд на карточке, окно, проверка перед отправкой),
`peekFreePacks(slug)` и `peekFreeCount(slug)` синхронно (подбор в сторе
и пределы количества — на Битриксе из данных в разметке); корзина,
оформление и карточка берут коробки только оттуда. В прототипе коробки
заведены на пяти позициях рыбы: настоящая одна — «Лосось нежно
подвяленный, в коробке» (веса сняты с grandgurme.ru 22.09.2026), остальные
четыре с придуманными весами (`⚠ ТЕСТОВЫЕ ВЕСА КОРОБОК`), у клыкача коробок
нет — под заказ.

**Каталог, поиск, избранное.** «Коробка 200 г» и «2 580 ₽» — номинальный
вес и цена по номиналу, без «≈» и без копеек; у клыкача под заказ то же
самое. Одна функция `priceText` в `model.js` (просто `formatPrice`),
приставка «≈ » с неразрывным пробелом остаётся в `category-copy.js` для
карточки и сумм. «В корзину» из сетки кладёт коробку по умолчанию
(ближайшую к номиналу); упёрлось в число свободных — тост «На складе
4 коробки, больше положить нельзя». Цена в карточке может отличаться
от каталожной на вес конкретной коробки («2 606 ₽ за коробку 202 г»
против «2 580 ₽» в сетке) — это и есть плата за «в каталоге стандарт».

**Карточка** — см. «Карточка товара → Позиция в коробках»: один селектор
`.boxsel` (`src/js/product/box-picker.js`), список весов — общий компонент
`src/js/components/box-list.js` (он же в окне корзины), выбор и степпер —
одно состояние, «В корзину» кладёт ровно отмеченные
(`addWithToast(product, qty, { packIds })`).

**Корзина.** У снимка позиции поле `boxes: { nominalG, pricePerKg, packIds }`
(`packIds` — выбранные коробки в порядке выбора), у обычной — `null`;
`CART_VERSION` 4, версии 2 и 3 читаются, у позиции, ставшей коробочной,
`boxes`, `price` и `note` берутся из каталога; поле `picked` записей 22.09
не читается. **У строки в наличии выбранных коробок всегда ровно `qty`**
(`fitPacks` в `store.js` при `add`, `setQty`, `setPacks` и при чтении записи):
лишние с конца убираются, недостающие подбираются ближайшими к номиналу из
свободных, не выбранных в строке, проданные выпадают. «+» добавляет
ближайшую свободную, «−» убирает последнюю добавленную; `add` с `packIds`
из карточки складывает отмеченные с уже лежащими; слияние гостевой корзины
при входе складывает выбор обеих. Количество не больше свободных, `add`
и `setQty` обрезают сами. Одна функция суммы строки `lineSum` (`summary.js`)
→ `{ value, approx }`: коробки выбраны (их ровно `qty`) или строка заказа
с коробками — сумма цен коробок, точно; коробка под заказ — `price × qty`
приблизительно. Строка: «Коробки 202 и 204 г» и точная сумма, рядом
`button.link-btn[data-pick]` «Выбрать другие» (одна коробка — «Выбрать
другую», `aria-label` «Выбрать другие коробки: {название}») →
`<dialog class="dialog dialog--boxes">` (`src/js/cart/box-dialog.js`: все
свободные по возрастанию веса, флажки или радиокнопки при одной,
«204 г / 2 631,60 ₽», при n отмеченных остальные выключены, «Выбрано 2 из 2»,
«Готово» → `setPacks`, «Отмена», «Подобрать автоматически» → ближайшие
к номиналу; Esc и клик по затемнению — без изменений, фокус на ссылку);
коробка под заказ — «Коробка ≈ 200 г · взвесим при фасовке» и «≈ 1 980 ₽»,
ссылки нет. Сводка при approx (только из-за коробок под заказ) — «≈ 11 871,20 ₽»
и «Коробки под заказ взвесим при фасовке — точную сумму сообщим СМС.»,
полоса на телефоне с «≈».

**Оформление.** Выбора коробок нет: ни блока «Вес коробок», ни окна.
В скрытом тексте миниатюры состава — веса («Коробки 202 и 204 г»). Есть
коробки под заказ — у шага «Оплата» один вариант «При получении»
и примечание; признак входит в подпись состава страницы (`signatureOf`).
**Перед отправкой** выбранные коробки проверяются заново (`verifyBoxes`):
купленную, пока заполняли форму, заменяет ближайшая свободная, не выбранная
в заказе, над составом сводки `p.summary__notice[data-box-notice]`
«Коробку 202 г (Лосось нежно подвяленный, в коробке) только что купили.
Положили 206 г — 2 657,40 ₽. Проверьте сумму и оформите заказ ещё раз.»
(`role="alert"`, фокус на нём), сводка пересчитана, заказ не отправлен;
следующее нажатие отправляет. Свободных не осталось — «Коробки {название}
закончились. Уберите позицию или вернитесь в корзину.» со ссылкой, отправка
стоит. **В заказ** уходит `boxes: { nominalG, pricePerKg, packs: [{ id,
weightG, price }], approx }` у позиции (коробки по возрастанию веса)
и `totals.approx` у записи; на «Заказ принят», странице заказа в кабинете
и в строке истории — веса, точные суммы, итог с «≈» и строкой «Точную сумму
сообщим СМС после фасовки.» при approx. «Повторить заказ» кладёт коробочную
позицию с теми же коробками, пока они свободны; иначе подбор. **Склад
прототипа после заказа не уменьшается.**

**Демонстрации:** `/cart?demo=boxes` (лосось × 2 — 202 и 204 г, осётр

### Перенос на Битрикс

Граница проведена так, чтобы менялись два файла, а не страницы:

* **`storage.js`** → запросы к `sale.basket`. `store.js` и все страницы остаются;
* **`submit.js`** (`submitOrder`, `getOrder`) → `sale.order`. Форма, проверка полей
  и страница успеха остаются.

Функции разметки принимают простой объект позиции и о хранилище не знают. Счётчик
шапки подписан на `cart:change` и стартовое число не перерисовывает: на Битриксе
его отдаёт сервер из `sale.basket`, и оно правдивее браузерного. Стили новых страниц
подключены в `src/bitrix/main.js`; сами страницы и строка наличия в шаблоне
`catalog.section` на Битриксе ещё **не перенесены** — это отдельный заход.

### Модель наличия

Остатки у заказчика ведутся, `inStock` считается достоверным. У чёрной икры
возвращены флаги выгрузки: на складе 4 позиции из 52 (`IN_STOCK_1C` в
`catalog-products.js`) — раньше там стояло `true` у всех.

**Строка «Наличие»** стоит над панелью фильтров на всех разделах: левая капсула —
база выдачи и не кнопка, правая «+ и под заказ» — чекбокс, состояние в `?stock=all`.
Позиции под заказ идут после наличия при любой сортировке. С 16.09.2026 они не
приглушаются и не подписываются «· под заказ»: вид говорит метка `.stock-tag`
(«Под заказ · 7 дней» или «Через менеджера» — по разделу, см. «Три вида позиции»). Тумблер «В наличии» из пилюль и переключатель из боттом-шита убраны.
Фасовка икры переехала из табов в пилюлю; **ключ остался `format`, а не `pack`**: на нём
держатся свойство товара, `?format=` и ссылки подкатегорий из мега-меню.

**Решение, которого не было в задаче: принудительный показ под заказ считается
по выбранному, а не только по разделу.** На складе только осётр, и человек, нажавший
«Белугу», при правиле «по разделу» получил бы пустую сетку и выключенную капсулу —
ровно та поломка, от которой правило защищает. Поэтому:

* нет наличия во всём разделе — «Сейчас со склада нет · показываем под заказ»;
* нет наличия по выбранному — «По выбранному со склада нет · показываем под заказ»;
* числа у опций фильтров считаются по тому же правилу — сколько человек увидит,
  выбрав опцию. Иначе у «Белуги» стоял бы ноль.

Логика — `stockView` / `applyStock` в `src/js/catalog/model.js`, веток по названию
раздела нет.

### Корзина

Строки через волосяную линию, группами по виду позиции (см. «Три вида позиции»).
Страница перерисовывается точечно по `id`: перерисовка всего списка сбрасывала бы
фокус со степпера. После удаления строки фокус уходит на соседнюю, после последней —
на заголовок. Позиций «по запросу» в заказе больше нет:
корзина из одной икры без цен — это заявка, сводка пишет «Менеджер уточнит цену
и срок поставки…», кнопка — «Оформить заявку». Ниже 1024 px итог и кнопка встают полосой внизу
экрана; полоса прячется, когда в кадре кнопка самой сводки. Виджета эксперта на
корзине и оформлении нет: его кнопка легла бы на эту полосу.

### Оформление

Шесть блоков с цифрой в Prata, подписи — надзаголовок фильтров. **Оформление без
входа остаётся** (17.09.2026): гостю вход предлагается одной строкой над первым
шагом («Покупали у нас раньше? Войдите — подставим контакты и адреса.») и ничего
не блокирует. Вошедшему имя, телефон и почта подставлены из кабинета и остаются
редактируемыми; сохранённые адреса стоят карточками-радиокнопками на основе
`.cap`, выбран основной, последняя карточка — «Другой адрес»; под полями нового
адреса — чекбокс «Сохранить адрес в кабинете» (при десяти адресах — строка
вместо него). В `payload` уходят `contact.userId` и `order.addressId` либо новый
адрес; отмеченный адрес сохраняет `submitCheckout`. Корзина при входе
складывается с корзиной кабинета, при выходе остаётся в кабинете. Вход сменился
в соседней вкладке — корзина под формой не переключается, над формой строка
с кнопкой «Обновить», отправка выключена.
Общие поля, капсулы и чекбокс вынесены из `checkout.css` в
`components/form.css` без правок правил: собранный `app.css` Битрикса до и после
выноса даёт один и тот же список селекторов (1290), кадры оформления на 375
и 1440 совпадают попиксельно.
Ошибки — по уходу с поля и при отправке, текстом под полем с `aria-invalid`; на вводе
ошибка только снимается. Фокус при отправке — на первое поле с ошибкой. Город
зафиксирован (Москва), подсказка ведёт на `/delivery`. Дни раньше готовности заказа
выключены и объяснены; при заказе из наличия и предзаказа — выбор одной или двух
доставок.
Пустая корзина на `/checkout` возвращает на `/cart`.

**«Заказ принят»** берёт номера из адреса (`n` — заказ, `r` — заявка); без обоих —
содержимое `/404`, документ из другого браузера — номер и шаги без состава. При двух
доставках — два шага доставки со своими датами; заявка с заказом — отдельный блок
«Заявка №… у менеджера»; одна заявка — «Заявка №… отправлена». Вошедшему кнопка
«Мои заказы» ведёт прямо на этот заказ в кабинете (при одной заявке — на заявку).
Гостю вместо кнопки под шагами стоит блок «Следите за заказом в кабинете»
со входом по номеру из заказа: номер подставляется в поле, после входа заказ
привязывается к кабинету и открывается.

## Личный кабинет, вход и избранное

Собрано 17.09.2026 в прототипе. На стенд Битрикса переносит Cowork по записке
`PERENOS-kabinet-i-izbrannoe.md` (страницы, формы данных, события, разметка
для общих модулей) — PHP в этой задаче не писался.

### Решения Дениса

1. **Вход только по номеру телефона и одноразовому коду.** Паролей, входа
   по почте и кнопок «Войти через Google / Apple» нет. По российским правилам
   авторизации номер телефона — разрешённый способ входа; VK ID, Яндекс ID
   и Сбер ID тоже разрешены — это второй темп.
2. **Вход и регистрация — один сценарий:** номер, код, и для нового номера —
   короткий шаг «Как к вам обращаться».
3. **Оформление без входа остаётся.** Вход на оформлении — одна строка.
4. **Заказы и заявки, оформленные без входа, попадают в кабинет** того, чей
   номер указан в контактах, при каждом входе с этим номером.
5. **Избранное работает без входа** и хранится в браузере; при входе переходит
   в кабинет, в браузере очищается; после выхода в браузере пусто. Адрес —
   `/favorites`.
6. **Корзина при входе складывается** с корзиной кабинета: одинаковые позиции
   не удваиваются, остаётся большее количество. При выходе корзина остаётся
   в кабинете, в браузере — пустая.
7. **Отменить или изменить заказ из кабинета нельзя** — на странице заказа
   для этого связь с менеджером.
8. **Сердец на витрине главной `#shop` нет.** Сердце есть в сетке раздела,
   на карточке товара, в её лентах, на обзоре кабинета и на `/favorites`.
9. **Не делаем в этой задаче:** VK ID, Яндекс ID, Сбер ID, бонусы и лояльность,
   сохранённые карты, получателей, отзывы. «Сообщить о поступлении» сделано
   22.09.2026 — раздел «Лист ожидания» ниже.

### Решения, принятые иначе

| В задании | Сделано | Почему |
|---|---|---|
| `favorites/store.js` «сохраняет через `api.js`», все функции `api.js` асинхронные | у `api.js` есть синхронная `peekFavorites()` для первого чтения | стору нужны `has()` и `count()` сразу: сердца и счётчик шапки рисуются в первом кадре. На Битриксе это данные из разметки страницы |
| стор «выбрасывает снятую с продажи позицию при чтении и сообщает, сколько их было» | выбрасывает из состояния при чтении, а **из хранилища убирает** только когда `/favorites` показала строку о них (`confirmDropped`) | счётчик шапки читает стор на каждой странице; иначе строку «больше не продаются» съедала бы первая же страница сайта |

## Репозиторий и ветки

**Прототип и Битрикс — не две версии сайта, а две сборки одних исходников.**
`npm run build` собирает прототип для Vercel, `npm run bitrix` — ассеты шаблона из тех
же `src/data`, `src/js`, `src/styles`. Поэтому они живут в одной ветке `main`, а не в
двух долгоживущих: иначе каждую правку шапки или карточки пришлось бы переносить из
ветки в ветку, и версии разошлись бы за неделю.

Что лежит в репозитории для Битрикса:

| Путь | Что это |
|---|---|
| `bitrix/templates/grandgurme/` | шаблон сайта на PHP: шапка, подвал, панели, шаблоны компонентов каталога. Уезжает на сервер в `/bitrix/templates/` |
| `deploy-src/` | страницы для корня сайта на стенде (`/index.php`, `/catalog/`, `/product/`, пробная `/gg/`) |
| `src/bitrix/main.js`, `vite.bitrix.config.js` | точка входа и сборка одного `app.css` и одного `app.js` прямо в шаблон |
| `scripts/build-bitrix-data.mjs` | `src/data/*.js` → `include/generated.php` |
| `grandgurme-bitrix-build*.zip` | архив для заливки на стенд. **В git не хранится**, собирается заново |

**Файлы на стенде правятся не только сборкой.** Агент в админке Битрикса
пишет PHP прямо на сервере. Такие правки обязаны возвращаться в репозиторий
архивом до следующей заливки: 14.09 изменения фильтров каталога жили только
на стенде, и новая сборка из ветки их затёрла бы. Подробнее — в
`bitrix/templates/grandgurme/README.md`, «Наличие, корзина и оформление».

Порядок работы:

* задача — короткая ветка от `main` (`feature/cart-checkout`, `bitrix/catalog-section`),
  по готовности — pull request в `main`;
* изменения только для стенда — ветка с префиксом `bitrix/`, но в тот же `main`;
* что залито на стенд и на Vercel — отмечается тегом на коммите
  (`stand-2026-09-13`, `vercel-2026-09-14`): так видно, какая версия где стоит,
  без отдельной ветки.

**С 17.09.2026 порядок записан в `CLAUDE.md`** в корне — его читает любой
агент. Коротко: правда — `main` на GitHub; Cowork и Claude in Chrome, которые
не могут пушить, кладут патчи в `_patches/`, и следующая сессия Claude Code
применяет их первой; стенд заливается из коммита командой `npm run stand:deploy`
по SSH (запасной путь — архив `npm run stand` через `bitrix/install/stand-deploy.php`),
и оба пути сами сверяют суммы и останавливаются, если на стенде есть правки
не из репозитория. Файлы ядра сайта, которые
правились на сервере (`init.php`, `urlrewrite.php`), лежат в `bitrix/server/`,
настройки админки — в `bitrix/STAND-SETTINGS.md`.

### Заливка стенда по SSH (23.09.2026)

23.09.2026 на стенде появился SSH, и заливка перестала быть ручной процедурой
в админке. Команды:

* `npm run stand:drift` — что на стенде правили мимо репозитория;
  `npm run stand:pull -- /catalog/index.php` — забрать такой файл в его путь
  в репозитории (в Git Bash ведущий слеш писать нельзя — MSYS превратит его
  в путь к папке Git; там `npm run stand:pull -- catalog/index.php`);
* `npm run stand:deploy` — сухой прогон, печатает список изменений и
  останавливается; `npm run stand:deploy -- --yes` — копия перезаписываемого,
  заливка, манифест, сброс кеша и проверка, что страницы отдают 200.

Архив (`npm run stand`) и `bitrix/install/stand-deploy.php` остались запасным
путём: SSH может не ответить, а на боевом сайте его пока нет. Список файлов
у обоих путей один — `scripts/stand-files.mjs`, манифест один и тот же
(`/local/gg-stand/manifest.json`), так что пути можно чередовать. Подробный
порядок — в `CLAUDE.md`.

**Решения, принятые иначе**

| В задании | Сделано | Почему |
|---|---|---|
| `rsync` с машины на сервер, одним соединением с `ControlMaster` | Сборка уезжает одним `tar.gz` в `/home/deploy/.gg-stand-stage`, а `rsync` запускается уже **на сервере**, из этой папки в корень сайта. Флаги те же | На машине нет `rsync` (Windows, Git Bash его не несёт), а `ControlMaster` в OpenSSH для Windows не работает: мастер отваливается и оставляет мёртвый сокет. На Linux и macOS мультиплексирование включается само. Вход по ключу без пароля занимает доли секунды, так что несколько соединений ничего не стоят |
| `rsync -a` | `rsync -rlD`, то есть `-a` без `-t`, `-g`, `-o` и `-p` | `-g` и `-o` задание само запрещает. `-t` не нужен: сравнение идёт по контрольным суммам, а даты на сервере только шумели бы. `-p` пришлось убрать после первой же заливки — с ним `rsync` пытается подровнять права **существующей** папки `/bitrix` (она 0777) и падает: `deploy` ей не владелец. Без `-p` `--chmod` действует только на то, что `rsync` создаёт сам |
| Копии в `/var/www/bitrix.1grandgourmet.ru/gg-stand-archive/` | Копии уходят в `/home/deploy/gg-stand-archive/`, скрипт об этом предупреждает | В `gg-stand-archive` права `750 www-data:www-data` — группе записи нет, а `deploy` не владелец и `sudo` у него нет. Папка домой тоже вне корня сайта, nginx её не отдаёт. Как только на `gg-stand-archive` появится `g+w`, скрипт начнёт класть копии туда сам — он проверяет это при каждой заливке |
| Копия — папка `backup-<дата>-<коммит>/` с сохранением путей | Копия — файл `backup-<дата>-<коммит>.tar.gz` | В задании же и сказано, что откат делается строкой `tar -xf <копия> -C <корень сайта>`; распаковывать папку такой строкой нечем |
| `md5sum` на сервере через `xargs -0` батчами | `perl` с `Digest::MD5`, пути уходят через stdin в файл | `md5sum` считает сумму по байтам, а сверка идёт по содержимому с концами строк, приведёнными к `\n` (так делает `stand-deploy.php`, иначе файл, поправленный через админку, даст ложное расхождение). Список путей через stdin вообще снимает вопрос о длине командной строки, батчи не нужны |
| Проверка вхолостую на том коммите, что уже на стенде | Сначала настоящая заливка (`6e892f7` → `main`, восемь коммитов сверху: коробки, селектор веса, кабинет), и уже потом вхолостую — 0 файлов из 41 | `main` ушёл вперёд ещё до этой задачи, заливать вхолостую было нечего. Вышло к лучшему: на настоящей заливке вылезло падение на `-p`, которого пустая не показала бы, — а проверка вхолостую прошла следом, на том же коммите, с нулём файлов |
| — | На стенде теперь `main`, а не то, что было 22.09 | Стенд отставал на восемь коммитов. Задание этого не просило, но оно же и требует, чтобы стенд заливался из `main`; заодно это была единственная возможность проверить механизм на настоящих файлах |
| Кеш чистится целиком | Часть `bitrix/managed_cache` и `bitrix/stack_cache` удалить не получается | Эти файлы писал php-fpm (`www-data`) в подпапки без групповой записи. Битрикс перепишет их сам, но чтобы чистка была полной, нужен `chmod -R g+w` на три папки кеша — это root. Скрипт считает такие файлы и говорит об этом строкой, а не сотней строк `rm` |

Почему это понадобилось. 16.09 на стенд залили архив, собранный из `82132be`
с патчем поиска из Cowork. Патча не было в GitHub, а три коммита после
`82132be` (метка «Через менеджера», подсказка о раздельной доставке) не было
на стенде. Три места — три разные версии.
