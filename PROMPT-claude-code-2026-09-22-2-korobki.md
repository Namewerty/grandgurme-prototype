## 1. О чём это

Большая часть рыбы продаётся не на развес и не в фасовке с ровным весом,
а коробками: коробка «около 200 г» на деле весит от 174 до 238 г, и человек
платит за вес именно своей коробки. Каждая коробка уже нарезана, взвешена
и запечатана, её вес известен заранее, а 1С знает, какие коробки лежат на
складе.

Так это устроено на действующем сайте: https://grandgurme.ru/catalog/ryba_vyalennaya_sushennaya/losos-nezhno-podvyalenyy/
— 11 кнопок с весами от 174 до 238 г, цена меняется с весом (12 900 ₽ за кг,
от 2 244,60 до 3 070,20 ₽). Денису это не нравится: человека заставляют
выбирать между граммами и копейками, хотя большинству всё равно.

Решение Дениса:

- До оформления человек видит только приблизительные вес и цену: «Коробка
  ≈ 200 г», «≈ 2 580 ₽». Выбирать в карточке ничего не нужно.
- На оформлении система сама подбирает конкретные коробки — самые близкие
  к номинальному весу — и показывает точный вес и сумму. Кто хочет, меняет
  коробки по ссылке «Выбрать другие». Кто не хочет, этого списка не открывает.
- Раз вес известен заранее, заказ из коробок в наличии имеет точную сумму
  и оплачивается сразу, как обычный. Приблизительной остаётся только коробка
  под заказ, которой на складе ещё нет: её вес узнают при фасовке.
- Копейки в точной цене остаются как есть (12 900 ₽ × 0,174 кг = 2 244,60 ₽).
  Округлять точные суммы не нужно.

## 2. Данные

### Поля позиции

Позиция «в коробках» отличается от обычной тремя полями:

```js
{
  sale: 'box',          // продаётся коробками разного веса
  pricePerKg: 12900,    // цена за килограмм, ₽
  nominalG: 200,        // номинальный вес коробки
  packs: [              // свободные коробки на складе
    { id: 'losos-nezhno-podvyalenyy-174', weightG: 174 },
    …
  ],
}
```

Остальные поля позиции из них **выводятся**, руками не пишутся (сделай это
одной функцией-обёрткой при объявлении данных):

| Поле | Значение |
|---|---|
| `weightG` | `nominalG` — по нему работают пилюля «Вес» и сортировки по фасовке |
| `weightLabel` | «Коробка ≈ 200 г» |
| `price` | приблизительная цена коробки: `pricePerKg × nominalG / 1000`, округлённая до десятков рублей (12 900 × 0,2 = 2 580) — по ней работают пилюля «Цена», сортировки и `kindOf` |
| `inStock` | `packs.length > 0` |

Если `nominalG` не задан, номиналом считается медиана весов `packs`.

### Модуль `src/data/boxes.js`

Чистые функции, без DOM и хранилища:

- `isBox(item)`;
- `packPrice(pricePerKg, weightG)` — точная цена коробки в рублях с копейками:
  `Math.round(pricePerKg * weightG / 10) / 100`;
- `approxPrice(pricePerKg, nominalG)` — округление до 10 ₽;
- `pricePer100(pricePerKg)` — для строки «1 290 ₽ за 100 г»;
- `pickPacks(packs, n, nominalG, exclude = [])` — n коробок, самых близких
  к номиналу по модулю разницы; при равенстве — более лёгкая; результат
  по возрастанию веса. `exclude` — id коробок, которые брать нельзя;
- `weightsText([204, 206])` → «204 и 206 г»; три и больше — «174, 176 и 178 г»;
  одна — «204 г»;
- `packsWord(n)` — «коробка/коробки/коробок» через `plural()`.

### Граница «свободные коробки»

`src/js/cart/boxes.js`, два входа:

- `getFreePacks(slug)` — асинхронно, список свободных коробок с весами.
  Им пользуются оформление (подбор, окно выбора, проверка перед отправкой).
  На Битриксе — запрос к серверу (записка, раздел 9).
- `peekFreeCount(slug)` — синхронно, сколько свободных коробок. Им
  пользуются пределы, которые считаются без ожидания: `add` и `setQty`
  в `store.js`, максимум степпера на карточке и в корзине. В прототипе —
  из каталога; на Битриксе — из данных, которые сервер кладёт в разметку
  страницы.

Корзина, оформление и карточка берут коробки только отсюда.

- Цена: «≈ 2 580 ₽» и мелко рядом «за коробку».

- Характеристики: строка «Вес коробки — около 200 г» вместо «Вес — 200 г».

- Цена «≈ 1 980 ₽ за коробку».

## 5. Корзина

### Позиция корзины

К снимку позиции (`toLine` в `store.js`) добавляется поле `boxes`:

```js
boxes: {
  nominalG: 200,
  pricePerKg: 12900,
  packIds: [],          // выбранные коробки; пусто — подберём автоматически
  picked: null,         // null | 'auto' | 'manual' — кто выбрал packIds
} // у обычной позиции boxes: null
```

`CART_VERSION` → 4. Записи версий 2 и 3 читаются (`upgradeLine`): у позиции,
которая в каталоге стала коробочной, из каталога по слагу берутся `boxes`,
`price` и `note` — иначе у `losos-hk-korobka-146` останутся старые «1 шт,
146 г» и 1 883 ₽. Опиши версию 4 в шапке `storage.js`.

Слияние гостевой корзины при входе (`mergeGuestCart`) для коробочной позиции
обрезает количество по `peekFreeCount` и сбрасывает выбор (`packIds: []`,
`picked: null`).

Избранное хранит снимки и освежает их из каталога (`refresh` в
`favorites/store.js`): для коробочных позиций там же обновляются подпись
(`note`) и поля, по которым `priceText` узнаёт коробку.

- Количество коробочной позиции в наличии не больше числа свободных коробок.
  `add` и `setQty` обрезают сами. Если «в корзину» из сетки упёрлось в предел,
  вместо обычного тоста — «На складе {n} {коробка/коробки/коробок}, больше
  положить нельзя».
- Изменение количества сбрасывает выбор: `packIds: []`, `picked: null`.

### Как выглядит строка

| Случай | Подпись под названием | Сумма строки |
|---|---|---|
| 1 коробка, выбор не ручной | «Коробка ≈ 200 г» | «≈ 2 580 ₽» |
| n коробок, выбор не ручной | «{n} {коробка/коробки/коробок} по ≈ 200 г» | «≈ 5 160 ₽» |
| выбор ручной (сделан на оформлении) | «Коробки 204 и 206 г» / «Коробка 204 г» | точная, «5 289 ₽» |
| коробка под заказ | как в первых двух строках | «≈ …» |

Выбор, сделанный системой (`picked: 'auto'`), в корзине не показывается:
до оформления человек видит только приблизительное.

### Сумма

Одна функция суммы строки (в `cart/summary.js`, рядом с `lineSumLabel`)
возвращает `{ value, approx }`:

- ручной выбор или строка заказа с выбранными коробками — сумма цен коробок,
  точно;
- коробки без ручного выбора и коробки под заказ — `price × qty`, `approx: true`;
- обычная позиция — `price × qty`, точно.

`lineSumLabel`, `getTotals` и всё, что показывает суммы, берут её. У
`getTotals().order` появляется `approx` — есть ли в заказе хоть одна
приблизительная строка. `getTotals` принимает опцию, при которой выбор
`'auto'` тоже считается точным, — это нужно оформлению.

Сводка корзины при `approx` (пример — набор `/cart?demo=boxes`): «Товары ≈ 11 780 ₽», «Итого ≈ 11 780 ₽», под
итогом строка «Точную сумму посчитаем на оформлении — по весу коробок.»
Нижняя полоса на телефоне (`cart-bar`) — тоже с «≈».

## 6. Оформление

### Подбор при открытии

При открытии `/checkout` для каждой коробочной строки в наличии:

- выбор ручной и все его коробки по-прежнему свободны (`getFreePacks`),
  их число равно количеству — выбор остаётся;
- иначе — `pickPacks` по номиналу, результат пишется в строку
  с `picked: 'auto'`;
- свободных коробок меньше, чем в строке, — количество уменьшается до числа
  свободных, и в блоке «Вес коробок» у строки сообщение: «На складе осталось
  {n} {коробка/коробки/коробок} — оставили {n}.» Не осталось ни одной — как
  в «Проверке перед отправкой» ниже: сообщение и отправка стоит.

Коробочные строки под заказ не подбираются.

### Блок «Вес коробок» в сводке

В сводке оформления (`summaryMarkup`) сразу после миниатюр заказа
(`ul[data-items]`), до подписи и списка заявки, — блок с подписью «Вес коробок»
(стиль `summary__label`). Он есть, только
если в заказе есть коробочные строки. На каждую строку:

- название позиции;
- под ним: «2 коробки · 204 и 206 г» (в наличии) или «1 коробка · взвесим
  при фасовке» (под заказ);
- справа сумма: точная для коробок в наличии, «≈ …» для коробок под заказ;
- у коробок в наличии — ссылка-кнопка «Выбрать другие»
  (`aria-label`: «Выбрать другие коробки: {название}»).

Строки «Товары» и «Итого» — точные, если коробок под заказ нет; иначе «≈ …».

### Окно выбора коробок

«Выбрать другие» открывает `<dialog class="dialog dialog--boxes">`
(`showModal()`, как в `profile.js`; Esc и «Отмена» закрывают без изменений,
фокус возвращается на ссылку).

- Заголовок `h2`: название позиции.
- Подводка: «{цена за 100 г} за 100 г. Отметьте {n} {коробку/коробки/коробок}
  из тех, что есть на складе.»
- Список всех свободных коробок по возрастанию веса. При n = 1 — радиокнопки,
  иначе флажки. Строка: слева «204 г», справа «2 631,60 ₽». Отмечены текущие.
- При n > 1: когда отмечено n, неотмеченные флажки выключаются (подсказка
  под списком: «Чтобы выбрать другую, снимите отметку с одной из выбранных.»).
  Счётчик «Выбрано {k} из {n}», `aria-live`.
- Кнопки: «Готово» (сплошная, активна при k = n) и «Отмена»; ниже ссылка-кнопка
  «Подобрать автоматически» — возвращает подбор по номиналу и закрывает окно.
- «Готово» пишет выбор в строку с `picked: 'manual'`; сводка пересчитывается.
- Стили — `dialog.css`, модификатор `.dialog--boxes`: список с прокруткой
  внутри окна, если коробок больше, чем помещается; на телефоне окно на всю
  ширину с полями `--gutter`. `dialog.css` в `src/checkout.js` сейчас не
  подключён — подключи. На странице работает Lenis: прокручиваемому списку
  нужен `data-lenis-prevent`.

### Оплата

- Заказ без коробок под заказ — шаг «Оплата» как сейчас.
- Есть коробки под заказ — точной суммы у заказа нет, и оплатить его онлайн
  сейчас нельзя. У шага один вариант, «При получении» (`value: 'on-receipt'`,
  тот, что уже есть в `payment.options`), и примечание строкой `ready-line`
  (как `orderOnly`): «В заказе есть коробки под заказ: их вес узнаем при
  фасовке. Такой заказ оплачивается при получении, точную сумму сообщим СМС
  заранее.» Это касается и заказа с двумя доставками: обе оплачиваются при
  получении.
  В `checkout-copy.js` рядом пометка `⚠ ПОДТВЕРДИТЬ У ЗАКАЗЧИКА`: когда
  эквайринг начнёт выставлять счета, сюда добавится оплата по ссылке после
  фасовки. Строку — в «Что осталось
  предварительным».

### Проверка перед отправкой

Перед `submitCheckout` выбранные коробки проверяются заново через
`getFreePacks`. Если какую-то уже купили:

- на её место ставится ближайшая к номиналу свободная, не выбранная в этом
  заказе;
- в блоке «Вес коробок» у этой строки появляется сообщение (`role="alert"`):
  «Коробку {old} г только что купили. Положили {new} г — {price}. Проверьте
  сумму и оформите заказ ещё раз.»
- сводка пересчитывается, заказ **не отправляется**; фокус на сообщение.
  Следующее нажатие отправляет.
- Свободных не осталось вовсе — «Коробки {название} закончились. Уберите
  позицию или вернитесь в корзину.» со ссылкой на корзину, отправка стоит.

В прототипе склад не меняется, поэтому покажи это демонстрацией:
`/checkout?demo=box-taken` — при первой отправке первая выбранная коробка
первой коробочной строки считается проданной (до перезагрузки страницы).
Параметр подключается только точкой входа прототипа, в сборку Битрикса не
попадает. Описать в README («Демонстрация»).

### Что уходит в заказ

Позиция заказа с коробками (`collectPayload` → `submitCheckout` → запись
заказа) несёт:

```js
boxes: {
  nominalG, pricePerKg,
  packs: [{ id, weightG, price }],  // пусто у коробок под заказ
  approx: false,                    // true — коробки под заказ
}
```

У записи заказа `totals.approx`.

Состав шагов оформления сейчас пересобирается по `signatureOf(plan)`
(`checkout-page.js`). Добавь в подпись признак «есть коробки под заказ»:
состав корзины может поменяться в соседней вкладке, и шаг «Оплата» должен
пересобраться вместе с ним.
Сумма заказа считается той же функцией суммы строки. Склад прототипа после
заказа не уменьшается — написать в README.

## 7. Где ещё видно коробки

- «Заказ принят» (`success-page.js`): подпись строки — «Коробки 204 и 206 г»
  или «Коробка ≈ 200 г · взвесим при фасовке»; сумма точная или «≈ …»; итог
  с «≈», если `totals.approx`, и строкой под ним «Точную сумму сообщим СМС
  после фасовки.»
- Кабинет, страница заказа (`pages/order.js`) — то же. Строка истории
  (`order-row.js`, `getHistory`): у `HistoryRow` поле `approx`, сумма с «≈».
- «Повторить заказ» (`reorder`): коробочная позиция кладётся с тем же числом
  коробок, `packIds: []`, `picked: null`.
- `?demo=account` (`account/demo.js`): строки заказов там собираются руками
  (`line()`), а суммы — `price × qty` (`totalsOf`). Переведи их на те же
  функции, что у корзины и заказа, иначе коробочные строки посчитаются
  неверно. Позиции, которые стали коробочными (`losos-hk-korobka-146`,
  `losos-apelsin-hk-168` в демонстрационных заказах), получают коробки через
  `pickPacks` — у оформленного заказа вес уже известен, «≈» там быть не должно.
  В один из заказов добавь строку `losos-nezhno-podvyalenyy-korobka`, 2 коробки
  204 и 206 г, 5 289 ₽.
- `/cart?demo=boxes` (новый набор в `cart/demo.js`):
  `losos-nezhno-podvyalenyy-korobka` × 2, `osetr-hk-korobka-250` × 1,
  `klykach-file-hk-206` × 1, `losos-file-hk-klassicheskiy-100` × 1.

## 9. Записка для переноса на стенд

Файл `PERENOS-korobki.md` в корне, по образцу `PERENOS-kabinet-i-izbrannoe.md`.
PHP не писать. Обязательно:

1. **Данных для этого на стенде сейчас нет.** Пример: «Лосось нежно
   подвяленный (в коробке)», артикул GGRBLS009. На grandgurme.ru 22.09 у него
   11 коробок в наличии; на стенде он одна позиция с единицей «кг», ценой
   1 290 ₽ за 100 г и без списка коробок, в сетке — «Под заказ · 7 дней».
   (Попутно на стенде: в поиске этот товар «1 290 ₽ · под заказ», а на его
   карточке «Цена по запросу · через менеджера» — разобрать при переносе.)
2. Что нужно от 1С: по каждой коробочной позиции — список свободных коробок
   с кодом и весом, цена за килограмм и номинальный вес. Удобнее всего —
   характеристиками товара, которые Битрикс принимает как торговые
   предложения (коробка = предложение с количеством 1). Как 1С отдаёт коробки
   grandgurme.ru, знает тот, кто ведёт 1С; спросить его. Обмен самим сайтом
   не менять. Какие позиции коробочные — признак «Мера товара» =
   «Фасованный» (38 позиций на 16.09) — сверить с 1С.
3. Корзина `sale.basket`: строка на уровне товара с количеством коробок
   и свойствами (номинал, ручной выбор); при создании заказа — строки по
   выбранным предложениям с ценой по весу. Резерв, проверка «коробку купили»
   на сервере при отправке — тот же сценарий, что в прототипе.
4. `getFreePacks` — запрос к серверу; остальные функции `boxes.js` переезжают
   как есть.
5. Заказ с коробками под заказ пока оплачивается только при получении.
   Оплата по ссылке после фасовки появится, когда эквайринг начнёт выставлять
   счета; решение по нему ещё не принято (пункт 4 в `trebovaniya-k-vygruzke-1c.md`).
6. Пока данных нет, позиции без списка коробок работают по-старому.
