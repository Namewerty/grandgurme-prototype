# Перенос на Битрикс: страницы раздела «Компания», партия 1

Записка, а не задание: в этой задаче стенд не трогали. Что сделано
в прототипе — README, «Страницы раздела „Компания“, партия 1».

Девять страниц: `/partners`, `/about`, `/brands`, `/production`,
`/documents`, `/corporate`, `/contacts`, `/faq`, `/storage`.

## 1. Страницы — файлами с разметкой, которую правят в админке

Руководство хочет менять тексты этих страниц визуальным редактором.
Поэтому каждая страница переезжает так же, как пилотная
`deploy-src/storage/index.php`:

1. `npm run info:snapshot` — готовая разметка `<main>` каждой страницы
   в `bitrix/info-snapshots/<адрес>.html`. Разметка собрана теми же
   функциями, что прототип, без скриптов, без массивов и циклов — только
   `<section class="ib ib--<тип>" data-ib="<тип>">` подряд.
2. Страница `deploy-src/<адрес>/index.php` по образцу
   `deploy-src/storage/index.php`: `define('GG_PAGE_CLASS', 'info')`,
   шапка, `SetTitle` / `description` (`lead` из `src/data/routes.js`),
   **содержимое снимка между `<main>` и `</main>` как есть**, подвал.
   В шапке шаблона для этих страниц — класс `is-info` на `<body>`
   и шрифт Cormorant Garamond (курсив 400/500), как в каркасе прототипа
   (`scripts/build-pages.mjs`, `FONTS_INFO`), и флаг `is-animated`
   до первой отрисовки.
3. Адрес — в `ADMIN_EDITED` (`scripts/stand-files.mjs`): после первой
   заливки страницу правит контент-менеджер, заливка её больше не трогает.
   Сам файл в заливку попадёт без правок списка: `collectEntries` там же
   берёт всё из `deploy-src/`. Папка `bitrix/info-snapshots/` на сервер
   не уезжает — это заготовка, а не файл сайта.

Контент-менеджер может копировать, удалять и переставлять блоки целиком —
каждый блок одна `<section>` без обёрток. Внутри блока менять можно тексты
и ссылки; `data-*` атрибуты, классы и `id` трогать нельзя: по ним блок
оживает. Строки условий, которых пока нет (`value: null` в данных),
в разметке отсутствуют — когда компания ответит, их добавят в админке
строкой `<div class="ib-table__row">…</div>` или пересоберут снимок.

## 2. Скрипт и стили блоков

- Сборка Битрикса (`vite.bitrix.config.js`, вход `src/bitrix/main.js`)
  сейчас блоков не содержит: `npm run bitrix` проходит, файлов
  `src/info/` в `app.js` нет. Для переноса — отдельный вход
  `src/bitrix/info.js`: стили `src/info/styles/**`, `src/alt2/alt2.css`,
  `character.css`, `origin.css`, затем `initBlocks(document.querySelector('#main'))`
  из `src/info/render.js`, `initScroll()` из `src/js/scroll.js` и
  `initCharacter()` / `initOrigin()`, если на странице есть их секции.
  `renderPage` на Битриксе не нужен: разметку отдаёт сервер.
- Файлов данных `src/data/info/*` скрипт на Битриксе не использует вовсе:
  `init*` читают всё из разметки (`data-*`, текст, ссылки). Проверено
  в прототипе: `/partners?snapshot=1` и остальные восемь адресов с этим
  параметром вставляют в страницу разметку снимка вместо сборки — блоки
  оживают тем же кодом (только на dev-сервере, в собранной версии
  параметра нет).
- Шапка: над тёмным первым экраном (вид `stage`) она прозрачная — узел
  с `data-hero` (`src/js/sections/header.js`, `watchHeaderState`). На
  Битриксе шапка серверная, скрипт тот же — правка уже в общем коде.

## 3. Две секции /alt2 остаются собираемыми скриптом

«Характер икры» (`/brands`) и «Происхождение» (`/production`) собираются
через DOM из `src/data/caviar-lines.js` и `src/data/origin.js` и правилу
переносимости не подчиняются — так же, как секции главной. В снимке на их
месте пустая `<section id="character" data-ib="alt2-character">` /
`<section id="origin" data-ib="alt2-origin">`. Вход `src/bitrix/info.js`
должен заменить их на `buildCharacter({ id: 'character', headless: true,
labelledBy: 'caviar-title' })` и `buildOrigin({ id: 'origin', headless: true })`,
как это делает `mountAlt2` в `src/info.js`. Их тексты в визуальном
редакторе не правятся — это данные, как паспорта линеек.

## 4. Заявки: инфоблок «Заявки с сайта» и письмо

Четыре формы: `partners` (дегустация), `documents` (пакет документов),
`corporate` (расчёт подарков), `contacts` (обратная связь). В прототипе
отправки нет: проверка полей, состояние «отправлено» и строка в консоли.

На Битриксе — так же, как заявка менеджеру из корзины (`gg_requests`,
`include/requests.php`, `bitrix/install/gg-requests-install.php`):

- инфоблок «Заявки с сайта» (`gg_site_requests`) с полями: «Форма»
  (список: partners / documents / corporate / contacts), «Страница»,
  имя, контакт, почта, компания или заведение, город, роль, тип заведения,
  что интересует, количество, дата, формат, тема, сообщение, UTM (пять
  полей), время. Скрипт установки — `bitrix/install/gg-site-requests-install.php`
  по образцу `gg-requests-install.php`, запуск `npm run stand:php -- … --mode=install`;
- почтовое событие `GG_SITE_REQUEST` с шаблоном письма на адрес отдела
  продаж (адреса по формам — вопрос к компании: для заведений в презентации
  v.eloev@grandgurme.ru, для документов и подарков — не названы);
- обработчик: AJAX-запрос формы (`form` в скрытом поле определяет тип),
  серверная проверка обязательных полей и согласия, запись, письмо, ответ
  JSON; `initForm` на успех показывает тот же блок «отправлено». Защита
  от спама — та же, что у заявки из корзины.

Согласие ведёт на `/consent/` и `/privacy/` — на стенде этих страниц
по-прежнему нет (README, «Что осталось до полного запуска»).

## 5. /storage на стенде

На стенде `/storage/index.php` — пилотная страница, которую правят в админке
(`ADMIN_EDITED`); в этой задаче `deploy-src/storage/index.php` не тронут.
Чтобы новая страница попала на стенд:

1. сохранить текущий текст страницы со стенда (`npm run stand:pull --
   /storage/index.php`), если контент-менеджер его правил;
2. **сознательно удалить** `/storage/index.php` на стенде — заливка
   страницы из `ADMIN_EDITED` не перезаписывает, это правило, а не баг;
3. положить в `deploy-src/storage/index.php` разметку из
   `bitrix/info-snapshots/storage.html` по пункту 1 и залить.

## 6. /about на стенде

На стенде по адресу `/about/` лежит демонстрационная страница магазина
одежды из поставки Битрикса. Её удаляют тем же осознанным действием,
а не заливкой: файл не наш, заливка его не трогает (список файлов —
`scripts/stand-files.mjs`).

## 7. Мелочи, которые всплывут при переносе

- **Подвал.** В прототипе строка копирайта —
  «© ООО «№1 Гранд Гурмэ», 2026. ИНН 9725174233» (`src/data/info/company-details.js`).
  На Битриксе подвал серверный, и `scripts/build-bitrix-data.mjs` подменяет
  строку на `'© №1 Гранд Гурмэ'` (`fn.php` дописывает год) — поменять там
  на `'© ООО «№1 Гранд Гурмэ»'` и дописать ИНН в `fn.php`.
- **Самовывоз.** `pickupPoints` (`src/data/offline.js`) теперь «Софийская
  набережная, 10», часы, метро и `open` / `close`. Оформление на стенде
  берёт адрес не отсюда — сверить со службой доставки «Самовывоз» в админке.
- **Флаги** `SHOW_PARTNER_NAMES` / `SHOW_COLLAB_NAMES`
  (`src/data/info/flags.js`) действуют при сборке снимка: с `false` названий
  в снимке нет. Включили флаг — пересобрать снимок и заменить блок
  в админке. Кадры под флагами (`media/info/collab/`, `event-night.jpg`,
  `geo/las-vegas.jpg`) на сервер не возить, пока флаг выключен.
- **Кадры** `/media/info/**` — на стенд партией, как `/media/alt2/`;
  медиа-манифест пересобирается (`npm run bitrix`). Права на кадры
  из ресторанов — вопрос к компании (`public/media/info/ИСТОЧНИКИ.md`).
- **Карта сайта стенда** (`urlrewrite.php`) для этих адресов не нужна:
  это обычные физические страницы.
