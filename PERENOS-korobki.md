# Перенос на 1С-Битрикс: товар в коробках с разным весом

Записка для Cowork: что сделано в прототипе 22.09.2026 и что должен повторить
стенд `bitrix.grandgurme.ru`. PHP здесь нет намеренно — только границы, формы
данных и разметка, которую ждут общие модули. Образец — `PERENOS-kabinet-i-izbrannoe.md`.

Прототип: `https://grandgurme-prototype.vercel.app`. Показ: `/cart?demo=boxes`
→ «Оформить заказ» → «Вес коробок» в сводке, «Выбрать другие»; проверка
перед отправкой — `/checkout?demo=box-taken`; карточки
`/product/losos-nezhno-podvyalenyy-korobka` и `/product/klykach-file-hk-206`.

> ⚠ **Данных для этого на стенде сейчас нет.** Пример: «Лосось нежно
> подвяленный (в коробке)», артикул GGRBLS009. На grandgurme.ru 22.09.2026
> у него 11 коробок в наличии от 174 до 238 г; на стенде он одна позиция
> с единицей «кг», ценой 1 290 ₽ за 100 г и без списка коробок, в сетке —
> «Под заказ · 7 дней». Попутно на стенде: в поиске этот товар «1 290 ₽ ·
> под заказ», а на его карточке «Цена по запросу · через менеджера» —
> разобрать при переносе (карточка и подсказки считают цену по-разному).
> Пока данных нет, позиции без списка коробок работают по-старому.

---

## 1. О чём это и что решено

Большая часть рыбы продаётся коробками: коробка «около 200 г» весит от 174
до 238 г, каждая уже взвешена и запечатана, 1С знает, какие лежат на складе.
На действующем сайте человек выбирает из 11 кнопок с весами. Решение Дениса:

- до оформления только приблизительные вес и цена: «Коробка ≈ 200 г»,
  «≈ 2 580 ₽», в карточке выбирать нечего;
- на оформлении система сама подбирает коробки, самые близкие к номиналу,
  показывает точный вес и сумму; «Выбрать другие» — окно выбора;
- заказ из коробок в наличии имеет точную сумму и оплачивается сразу;
  приблизительной остаётся только коробка под заказ (вес узнают при
  фасовке) — такой заказ оплачивается при получении;
- копейки в точной цене остаются (12 900 ₽ × 0,174 кг = 2 244,60 ₽).

## 2. Что нужно от 1С

По каждой коробочной позиции:

| Что | Зачем |
|---|---|
| список свободных коробок: код и вес каждой | подбор, окно выбора, проверка перед отправкой, предел количества |
| цена за килограмм | точная цена коробки `round(pricePerKg × weightG / 10) / 100` и приблизительная `pricePerKg × nominalG / 1000` до десятков рублей |
| номинальный вес коробки | подпись «Коробка ≈ 200 г», подбор «ближе всего к номиналу»; нет — медиана весов свободных коробок |
| признак «позиция в коробках» | сейчас предположительно «Мера товара» = «Фасованный» (38 позиций на 16.09.2026) — сверить с 1С |

Удобнее всего — **характеристиками товара**, которые Битрикс принимает как
торговые предложения: коробка = предложение с количеством 1, весом
в свойстве и ценой по весу. Как 1С отдаёт коробки grandgurme.ru, знает тот,
кто ведёт 1С, — спросить его; **обмен самим сайтом не менять**.

## 3. Данные и функции прототипа

### 3.1. Поля позиции (`src/data/catalog-products.js`, обёртка `withBoxFields`)

```
sale: 'box'          продаётся коробками разного веса
pricePerKg: 12900    цена за килограмм
nominalG: 200        номинальный вес; не задан — медиана весов packs
packs: [{ id: 'losos-nezhno-podvyalenyy-korobka-174', weightG: 174 }, …]
```

Выводятся, руками не пишутся: `weightG = nominalG` (пилюля «Вес», сортировки
по фасовке), `weightLabel` «Коробка ≈ 200 г», `price` — приблизительная цена
коробки до десятков рублей (пилюля «Цена», сортировки, `kindOf`),
`inStock = packs.length > 0`. `id` коробки — `<слаг>-<вес>`, при совпадении
весов — порядковый суффикс. У коробочных позиций `oldPrice: null`,
`isSale: false`: зачёркнутая цена рядом с приблизительной не имеет смысла,
пока скидка не задана за килограмм.

### 3.2. Чистые функции `src/data/boxes.js` — переезжают как есть

| Функция | Что делает |
|---|---|
| `isBox(item)` | `item.sale === 'box'` |
| `packPrice(pricePerKg, weightG)` | точная цена коробки с копейками |
| `approxPrice(pricePerKg, nominalG)` | до 10 ₽ |
| `pricePer100(pricePerKg)` | «1 290 ₽ за 100 г» |
| `pickPacks(packs, n, nominalG, exclude)` | n самых близких к номиналу по модулю разницы, при равенстве более лёгкая, результат по возрастанию веса; `exclude` — id, которые брать нельзя |
| `weightsText([204, 206])` | «204 и 206 г», «174, 176 и 178 г», «204 г» |
| `packsWord(n)`, `packsWordAcc(n)` | «коробка/коробки/коробок», винительный «коробку/…» |
| `boxLabel(nominalG)` | «Коробка ≈ 200 г» |
| `withBoxFields(product)` | обёртка при объявлении данных |

### 3.3. Граница «свободные коробки» — `src/js/cart/boxes.js`

| Функция | Прототип | На Битриксе |
|---|---|---|
| `getFreePacks(slug)` → `Promise<[{ id, weightG }]>` по возрастанию веса | из каталога | **запрос к серверу**: свободные предложения-коробки товара (остаток минус резерв) |
| `peekFreeCount(slug)` синхронно | из каталога | из данных, которые сервер кладёт в разметку карточки и строки корзины (`data-free-count`) |
| `findPack(slug, id)` синхронно | из каталога, и среди проданных | из разметки строки корзины: вес выбранных коробок |
| `markSold(ids)` | только демонстрация `box-taken` | не переносится |

Корзина, оформление и карточка берут коробки только отсюда. Склад прототипа
после заказа не уменьшается.

## 4. Корзина (`sale.basket`)

Строка корзины — **на уровне товара** с количеством коробок и свойствами
(`src/js/cart/store.js`, версия записи 4):

```
boxes: {
  nominalG, pricePerKg,
  packIds: [],          выбранные коробки; пусто — подберём на оформлении
  picked: null,         null | 'auto' (система) | 'manual' (человек в окне)
}                       у обычной позиции boxes: null
```

Правила, которые повторяет сервер:

- количество коробочной позиции в наличии не больше числа свободных коробок;
  `add` и `setQty` обрезают сами; «в корзину» из сетки кладёт одну коробку,
  упёрлось в предел — тост «На складе {n} коробок, больше положить нельзя»;
- изменение количества сбрасывает выбор (`packIds: []`, `picked: null`);
- слияние гостевой корзины при входе обрезает количество по свободным
  коробкам и сбрасывает выбор;
- сумма строки (`lineSum` в `cart/summary.js`): ручной выбор или строка заказа
  с коробками — сумма цен коробок, точно; без ручного выбора и под заказ —
  `price × qty`, приблизительно; `getTotals().order.approx` — есть ли
  приблизительная строка; на оформлении выбор `'auto'` тоже точный
  (`getTotals({ autoIsExact: true })`);
- подпись строки: «Коробка ≈ 200 г», «2 коробки по ≈ 200 г», после ручного
  выбора — «Коробки 204 и 206 г» и точная сумма; выбор системы в корзине
  не показывается; сводка при approx — «≈ 11 780 ₽» и строка «Точную сумму
  посчитаем на оформлении — по весу коробок.», полоса на телефоне с «≈».

Записи корзины версий 2 и 3 читаются: у позиции, ставшей коробочной,
`boxes`, `price` и `note` берутся из каталога по слагу.

## 5. Оформление

**Подбор при открытии** (`prepareBoxes`): для каждой коробочной строки
в наличии — ручной выбор остаётся, если все его коробки свободны и их
столько же, сколько в строке; иначе `pickPacks` по номиналу, `picked: 'auto'`.
Свободных меньше, чем в строке, — количество уменьшается, у строки сообщение
«На складе осталось {n} коробок — оставили {n}.»; не осталось ни одной —
«Коробки {название} закончились. Уберите позицию или вернитесь в корзину.»
и отправка стоит. Коробки под заказ не подбираются.

**Блок «Вес коробок»** (`.summary__boxes`, сразу после миниатюр заказа
`ul[data-items]`, до подписи и списка заявки; есть только при коробочных
строках): на строку `li.summary__box[data-box-line]` — название, «2 коробки ·
204 и 206 г» или «1 коробка · взвесим при фасовке», справа точная сумма или
«≈ …», у коробок в наличии `button.link-btn[data-box-pick]` «Выбрать другие»
(`aria-label` «Выбрать другие коробки: {название}»), под строкой
`p.summary__box-message` (при проверке — `role="alert"`). Строки «Товары»
и «Итого» точные, если коробок под заказ нет; иначе «≈ …».

**Окно выбора** — `<dialog class="dialog dialog--boxes">`, `showModal()`:
`h2` название, подводка «{цена за 100 г} за 100 г. Отметьте {n} коробки из
тех, что есть на складе.», список всех свободных коробок по возрастанию веса
(`ul.boxlist[data-lenis-prevent]`, строки `label.check.boxlist__label` —
при n = 1 радиокнопки, иначе флажки; «204 г» слева, «2 631,60 ₽» справа),
при n > 1 и отмеченных n остальные выключены и подсказка «Чтобы выбрать
другую, снимите отметку с одной из выбранных.», счётчик «Выбрано {k} из {n}»
(`aria-live`), «Готово» (активна при k = n) → `picked: 'manual'`, «Отмена»,
«Подобрать автоматически» → подбор по номиналу и `'auto'`. Esc и клик по
затемнению закрывают без изменений, фокус возвращается на ссылку. На стенде —
та же разметка; данные списка — из `getFreePacks`.

**Оплата.** Есть коробки под заказ — у шага один вариант, «При получении»
(`on-receipt`), и примечание «В заказе есть коробки под заказ: их вес узнаем
при фасовке. Такой заказ оплачивается при получении, точную сумму сообщим
СМС заранее.» — и для заказа с двумя доставками. В подпись состава страницы
(`signatureOf`) входит признак коробок под заказ: поменялся состав
в соседней вкладке — страница перечитывается.

**Проверка перед отправкой** (`verifyBoxes`, на стенде — сервер при создании
заказа, тот же сценарий): выбранные коробки проверяются заново; купленную
заменяет ближайшая к номиналу свободная, не выбранная в этом заказе,
у строки сообщение «Коробку {old} г только что купили. Положили {new} г —
{price}. Проверьте сумму и оформите заказ ещё раз.», сводка пересчитывается,
заказ **не отправляется**, фокус на сообщении; следующее нажатие отправляет.
Свободных не осталось — «Коробки {название} закончились…» со ссылкой
в корзину, отправка стоит. **Резерв** выбранных коробок на время оформления —
решение стенда (в прототипе резерва нет).

**Что уходит в заказ** (`collectPayload` → `submitCheckout`): позиция
с коробками несёт `boxes: { nominalG, pricePerKg, packs: [{ id, weightG,
price }], approx }` (`packs` пусто и `approx: true` у коробок под заказ),
у записи заказа `totals.approx`. На Битриксе при создании заказа — строки
по выбранным предложениям с ценой по весу; строка коробки под заказ —
по номиналу с пометкой, что сумма уточняется после фасовки.

## 7. Что есть только в прототипе

- `/cart?demo=boxes` — лосось нежно подвяленный × 2, осётр × 1, клыкач под
  заказ × 1, обычная позиция × 1;
- `/checkout?demo=box-taken` — при первой отправке первая выбранная коробка
  первой коробочной строки считается проданной (до перезагрузки);
- `?demo=account` — в заказе 90005 строка лосося 2 коробки 204 и 206 г,
  5 289 ₽; позиции, ставшие коробочными, получают коробки подбором;
- веса коробок четырёх позиций из пяти придуманы (`⚠ ТЕСТОВЫЕ ВЕСА КОРОБОК`
  в `catalog-products.js`), настоящие — только у лосося нежно подвяленного;
- склад после заказа не уменьшается.
