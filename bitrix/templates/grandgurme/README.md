# Шаблон «№1 Гранд Гурмэ» для 1С-Битрикс

Перенос прототипа «Перламутр и жесть» на Битрикс. Вариант C: вёрстка живёт
в шаблоне сайта, страницы отдаёт сам Битрикс, каталог и корзина в перспективе
собираются на родных компонентах. Headless не рассматривается.

Стенд: `https://bitrix.grandgurme.ru`, пробный адрес главной — `/gg/`.

---

## Что где лежит

```
/bitrix/templates/grandgurme/
  header.php            верх страницы: <head>, полоса, шапка, обе панели, мобильное меню
  footer.php            подвал, кольцо прогресса, виджет эксперта, подключение скрипта
  description.php       имя шаблона в админке
  .styles.php           классы для визуального редактора
  include/
    fn.php              вся серверная сборка обвязки + живое дерево каталога
    catalog-map.php     карта витрины: разделы сайта ← разделы инфоблока 4
    generated.php       ⚠ СГЕНЕРИРОВАН из src/data/*.js — руками не править
  assets/
    css/app.css         сборка Vite
    js/app.js           сборка Vite
/media/…                кадры прототипа (в корне сайта, не в шаблоне)
/gg/index.php           пробная главная
```

## Что рисует сервер, а что скрипт

**Сервер (PHP):** верхняя полоса, шапка, каталожная мега-панель, панель
«Компания», мобильное меню, подвал, кольцо прогресса.

Это карта сайта. Она обязана быть в исходном html: её читает поисковик,
по ней ходят с клавиатуры, и она должна работать при выключенном JS. Разметка
в `fn.php` повторяет разметку прототипа до класса — стили общие, и любое
расхождение видно сразу как сломанная вёрстка.

**Скрипт (app.js):** скролл-движок Lenis, анимации входа секций (GSAP +
ScrollTrigger), открытие панелей, строка поиска, переключатель темы, подстановка
изображений и видео (`data-media`), виджет «Подобрать с экспертом», заполнение
кольца прогресса — и **десять секций главной страницы**.

Секции главной остаются на скрипте намеренно. Их тексты пока лежат в
`src/data/*.js` прототипа и в инфоблоки не разложены. Переносить их в PHP
«как есть» — значит закрепить временные формулировки в разметке и потом
вычищать их вручную.

## Сборка

```
npm run bitrix      # данные + css + js прямо в папку шаблона
npm run bitrix:data # только include/generated.php
```

`scripts/build-bitrix-data.mjs` импортирует `src/data/nav.js`, `footer.js`,
`company.js`, `routes.js`, `media.js` и `src/js/icons.js` и выкладывает их
PHP-массивом. Источник правды остаётся один — модули прототипа. Переписывать
тексты и адреса руками в PHP нельзя: они разойдутся на первой же правке.

`vite.bitrix.config.js` собирает `src/bitrix/main.js` в один css и один js.
Дробить бандл на чанки незачем: Битрикс подключает свои скрипты сам, а один
модуль в футере проще и предсказуемее. Версия ассета в ссылке берётся из
времени файла (`gg_asset`), так что кеш сбрасывается сам.

## Как страница объявляет себя шаблону

```php
define('GG_HERO', true);      // на странице есть первый экран
define('GG_SECTIONS', true);  // странице нужны секции главной
require($_SERVER['DOCUMENT_ROOT'].'/bitrix/header.php');
```

`GG_HERO` управляет прозрачностью шапки над первым экраном и цветом логотипа.
Без него шапка сразу плотная — так и должно быть на внутренних страницах.

## Каталог

Мега-панель и каталожная колонка подвала строятся из **живых данных
инфоблока 4** при каждой отрисовке. Количество товаров считается запросом,
раздел без активных товаров уходит из меню сам: обещать покупателю пустую
страницу хуже, чем показать на одну строку меньше.

Перекладка учётного дерева в витрину живёт в `catalog-map.php` и только там.
Учётное дерево собрано под товароведа: весь ассортимент лежит внутри одного
раздела «_Магазин ГРАНД ГУРМЭ» (ID 16), «Подарочные наборы» спрятаны внутри
«Икры», три раздела по две-пять позиций стоят рядом с флагманом. Менять это
на стороне 1С запрещено, показывать покупателю нельзя — значит, перекладка
на витрине.

Подкатегории бывают двух видов, и путать их нельзя:

* `type => 'section'` — настоящий раздел 1С, есть ID и количество товаров;
* `type => 'filter'` — фасет (белуга, осётр, фасовка 50 г). Раздела под ним
  нет: в 1С «Икра черная» подразделов не имеет вовсе, различия лежат
  в свойствах товара. До сопоставления свойств такие карточки ведут
  на страницу раздела с параметром `?sub=…`.

## Технический долг первого захода

1. **Тексты главной перенесены как есть** из `src/data/*.js`. Все десять
   секций — временные формулировки прототипа. Разложить по инфоблокам.
2. **Числа в секции «Не только икра»** («230 позиций», «7 позиций») — из
   данных прототипа, снимок выгрузки от 20.08. Мега-панель уже считает
   вживую; эту секцию нужно перевести туда же.
3. **Ссылки ведут на адреса прототипа** (`/catalog/…`, `/about`, `/delivery`).
   Страниц под ними пока нет — до второго захода это 404.
4. **Видео первого экрана не залито** (лимит nginx, см. ниже). Работает
   постер — штатное поведение прототипа для медленных соединений.
5. **`?sub=` не фильтрует** — фасеты чёрной икры ждут сопоставления свойств.
6. Строка «Прототип. Не публичная оферта.» в подвале — из данных прототипа.

## Что выяснилось на стенде

* **Лимит запроса nginx ≈ 1 МБ.** Загрузка через файловый менеджер больше
  этого размера отдаёт `413 Request Entity Too Large`. Медиа (19 МБ) пришлось
  везти пачками по 800 КБ; видео (9,8 МБ) этим каналом не проходит вовсе.
  Лечится одной строкой `client_max_body_size` в конфиге nginx.
* **Отсутствующий файл в `/media` отдаёт 200 и html**, а не 404: nginx
  проксирует несуществующие пути в `bitrix/urlrewrite.php`. Проверять наличие
  файла по коду ответа бессмысленно — только по `Content-Type`.
* **Лицензия Битрикса закончилась 27.08.2026.** Обновления и исправления
  уязвимостей закрыты.
* **Цены из 1С лежат в типе «Интернет-магазин» (ID 2), базовым помечен
  пустой BASE (ID 1).** Пока не тронуто — на главной цены не выводятся.
  Чинить до вывода каталога, иначе штатные компоненты покажут товары без цены.
* **Раздел 52 «Канцтовары»** лежит на верхнем уровне рядом с корнем магазина.
  В витрину не включён, из инфоблока не удалён.

## Наличие, корзина и оформление (15.09.2026)

Перенесено агентом в админке по `PROMPT-bitrix-korzina.md`, файлы стенда
возвращены в репозиторий. Что где:

| Файл | Что в нём |
|---|---|
| `include/catalog.php` | модель наличия (`gg_stock_view`, `gg_catalog_count_shown`), порядок «наличие, потом под заказ» и своя разбивка по страницам (`gg_catalog_page`, параметр `?page=`), адреса со `?stock=all`, `gg_item_title`, `gg_product_shot`, остатки по ID |
| `include/cart.php` | корзина на D7 `\Bitrix\Sale\Basket`: строки, итоги, тексты сводки, даты, промокод в сессии, POST-обработчик |
| `include/checkout.php` | проверка полей, телефон, создание заказа `\Bitrix\Sale\Order::create`, заказы сессии |
| `components/bitrix/catalog.section/gg` | строка «Наличие», фасеты-пилюли раскрывающимся `<details class="drop">`, свой пейджер |
| `components/bitrix/catalog.element/gg` | статус под ценой, форма со степпером, «Узнать цену» |
| `deploy-src/cart`, `checkout`, `order-success`, `delivery` | страницы в корне сайта |

Скрипт поверх серверной разметки — `src/bitrix/qty-hydrate.js` (степпер),
`src/bitrix/purchase-hydrate.js` (полоса итога в корзине, способ получения на
оформлении), маска телефона на `input[data-phone-mask]`. Без скрипта всё работает.

**Чем Битрикс отличается от прототипа, и это не ошибки:**

* **остатки и цены живые.** На 15.09 у чёрной икры 6 позиций в наличии из 54,
  и цена есть у всех позиций — в прототипе снимок выгрузки от 20.08 (4 из 52,
  цен нет). Остатки бывают дробными (0,5 кг) — к целому не приводить;
* ключ фасовки — `pack`, а не `format`: на нём ссылки мега-панели стенда;
* предзаказ: 16.09 решено включить «Разрешить покупку при отсутствии товара»
  (поручено агенту, `PROMPT-bitrix-2.md`). Карточка показывает «В корзину»,
  если позиция в наличии или компонент отдал `CAN_BUY`; иначе — «Заказать
  у менеджера». Порядок заливки шаблона и включения настройки не важен;
* заказ пишется на анонимного покупателя, способ оплаты и всё, под что нет
  свойств заказа (квартира, домофон, дата, интервал, промокод), — в комментарий;
  кнопки «Мои заказы» на «Заказ принят» нет — кабинета нет;
* службы доставки, платёжные системы, типы плательщика и свойства заказа
  на стенде — демонстрационные «1С-Битрикс», ничего не заводилось.

**Не проверено: создание заказа.** Тестовый заказ не оформлялся — выгрузка
заказов в 1С уйдёт с первым же запросом обмена.

**Уроки этого захода:**

* **Правки на стенде 14.09 не попали в репозиторий** и едва не потерялись:
  новые сборки из ветки их затирали. Любая правка файлов на сервере — сразу
  архивом обратно в репозиторий, до следующей заливки.
* **Копии `*.bak-*` и архивы в корне сайта отдаются nginx как обычные файлы**
  (проверено: код 200, исходники PHP скачиваются). Копии перед правкой делать
  вне корня сайта или сразу удалять после проверки.
* класс `.pager` был занят дважды — пейджер ленты переименован в `.rail-pager`;
* `markCurrentLinks` помечал активными все ссылки документа — ограничен
  навигацией, а ссылки с запросом сверяются по запросу.

Задание — `PROMPT-zakaz-i-zayavka.md`, перенос — `PROMPT-bitrix-3-zakaz-i-zayavka.md`.

| Файл | Что в нём |

| `include/cart.php` | строки с видом, группы, итоги только по заказу, переносы между корзиной и заявкой (`gg_cart_sync`), перехват `ADD2BASKET` с тостом |
| `include/checkout.php` | три режима, проверка полей для них и для двух отгрузок, заказ с двумя `Shipment` |
| `include/fn.php` | `gg_cart_count` считает и заявку |

| `deploy-src/cart`, `checkout`, `order-success`, `delivery`, `product` | страницы |
| `bitrix/install/gg-requests-install.php`, `…-uninstall.php` | скрипты для командной PHP-строки, на сервер не заливаются |

**Модель.** Вид считается при каждой отрисовке по живым данным. В наличии и под
заказ лежат в корзине Битрикса и уходят в заказ; по заявке — в cookie `gg_request`
(JSON `{"ID": количество}`, ≤ 30 позиций, 30 дней, `path=/`, `Secure`, `HttpOnly`,
`SameSite=Lax`, пишется `setcookie()` до `LocalRedirect`). При чтении cookie
проверяется, что товары существуют и активны. Позиция корзины, ставшая заявкой,
переезжает в cookie; позиция заявки, которую снова можно купить, — в корзину
(`\Bitrix\Catalog\Product\Basket::addProduct`); не принял Битрикс — остаётся молча.
Уведомление о переносе — над группами корзины.

**Заявка.** Отправленная заявка — элемент инфоблока `gg_requests` (тип `gg_service`,
без индексации, «Все пользователи» — нет доступа), свойства `CUSTOMER_NAME`, `PHONE`,
`EMAIL`, `CONTACT_WAY`, `ITEMS` (HTML-таблица), `ITEMS_JSON`, `QUESTION`, `ORDER_NUMBER`,
`STATUS`. Инфоблок ищется по коду, значения списков — по `XML_ID`. Письмо — событие
`GG_MANAGER_REQUEST`. Номер заявки — ID элемента. Защита от спама:
`check_bitrix_sessid()`, скрытое поле `gg_company_site`, не больше трёх заявок
с сессии за 10 минут. В заказы и в обмен с 1С заявка не попадает.

**Порядок отправки.** Сначала заказ; не создался — ошибка на форме, заявка не
создаётся. Заказ создан, заявка нет — «Заказ принят» со строкой «Заявку отправить
не удалось, позвоните нам» и телефоном. Успех — cookie заявки очищается.

**Две доставки.** Две записи в `ShipmentCollection` на ту же службу; в первой позиции
в наличии, во второй под заказ; в `COMMENTS` каждой — дата и интервал; в комментарии
заказа обе строки. Сервер рисует оба подблока, `src/bitrix/purchase-hydrate.js`
показывает выбранный.

**Тост.** Стенд не подтверждал добавление в корзину никак: `catalog.element` после
`ADD2BASKET` уводит на ту же карточку. Теперь `/product/index.php` перехватывает
запрос до компонента, кладёт позицию D7, пишет тост в сессию; после редиректа
тост рисуется разметкой `.toast` и прячется скриптом.

**Не проверено:** PHP в окружении разработки нет — код не исполнялся, синтаксис
проверен парсером `php-parser`. Заказ с двумя отгрузками не создавался (заказов на
стенде не оформляем) — в промпте агента есть сухой прогон без `save()`.

## Поиск, название для печати, вес и артикул (16.09.2026)

Сделано в Cowork по разбору стенда через админку.

**Поиск был сломан в двух местах.** Подсказки в шапке искали по данным
прототипа, зашитым в `app.js`: у чёрной икры там нет цен, отрисовка падала
на первой же позиции, и на «икра белуги» панель оставалась пустой; ссылки
вели на слаги прототипа. «Показать все результаты» открывал `/search/` —
страницу демо-магазина с `bitrix:search.page`, настроенным на инфоблоки
демо-одежды (`iblock_catalog`), и на любой запрос отвечал «ничего не найдено».

| Файл | Что в нём |
|---|---|
| `include/search.php` | поиск по витрине: основы слов морфологией модуля `search`, подстрока в `SEARCHABLE_CONTENT` (рабочее наименование, название для печати, описание), точное совпадение артикула и кода 1С, ранжирование |
| `/search/suggest.php` | JSON подсказок для шапки, без шаблона, `NO_KEEP_STATISTIC` |
| `/search/index.php` | страница результатов в разметке каталога; демо-страница заменена |
| `src/js/nav/search.js` | параметр `remote`: на Битриксе выдача с сервера, задержка 250 мс, кеш и отмена устаревших ответов, последние запросы в `localStorage` |
| `include/product-info.php` | название для печати, вес, весовой товар, артикул, цена на витрине |

Полнотекстовый индекс модуля поиска не используется: он находит только целые
слова, а подсказкам нужно недописанное («икра бел»). Товаров меньше тысячи,
запрос подстрокой — десятки миллисекунд. Сравнение в базе
(`utf8mb4_0900_ai_ci`) не различает регистр и «ё».

**Витрина — как на grandgurme.ru.** В сетке каталога, поиске и подсказках
у товара название, вес и цена, больше ничего. В карточке над названием мелко
«Артикул …», под названием вес. Характеристик, упаковки, кодов 1С и капсул
«Фасовка» на витрине нет: в выгрузке признаки заведены разными словами
(«х/к» и «Холодное копчение», «Коробка» и «Банка стекло 180 г»), и выведенные
как есть они дают разнобой подписей. Раньше подпись под названием в сетке
была то упаковкой, то артикулом — это убрано. Характеристики появятся, когда
их заведут единообразно. Текст «Хранение» про осетровую икру — только у
чёрной икры.

**Название для печати.** 1С отдаёт его полем «ПолноеНаименование», модуль
обмена кладёт в «Описание для анонса» (`PREVIEW_TEXT`). Заполнено у всех 924,
у 162 отличается от рабочего наименования. Показывается целиком — в карточке,
сетке, корзине, заявке, поиске и `<title>`. Запасной вариант — рабочее
наименование — только для брака: пусто, служебная строка «<Рабочее
наименование будет сформировано по шаблону>», одно слово при рабочем из трёх
и больше (20 позиций на 16.09, в основном чай NINA’S PARIS).

**Вес.** Одно правило: число с единицей берётся из первого источника, где
оно есть, — «Вес нетто», «Нетто», «Упаковка», название для печати, рабочее
наименование — и пишется одинаково: «50 г», «0,5 л», «60 × 2 г». Веса нет
нигде (140 позиций на 16.09, в основном бакалея и напитки) — строки веса нет.

**Весовой товар** — базовая единица «кг» (179 позиций, почти вся рыба). Цена
в 1С за килограмм; витрина, как grandgurme.ru, пишет «100 г» и цену за 100 г.
Корзина Битрикса при этом считает килограммами: в строке корзины «1 кг»
и цена за килограмм. ⚠ Шаг продажи (100 г или 1 кг) решается вместе
с весовым сценарием; до него витрина и корзина говорят о разных количествах.
